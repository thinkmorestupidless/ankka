# Python review checklist (3.11+, typed, uv/ruff/mypy or pyright)

Research notes for the language-specific pass an AI reviewer runs after the general checks.
Compiled 2026-10-23 from the primary sources below. Each checklist item names the signal to look
for in a diff, why it matters, and the source; a ruff rule code is given wherever one exists so the
reviewer can skip the item when the repository already runs that rule.

## 2. Detecting the language and version

**Files.** `*.py`, `*.pyi` (stubs: only PYI rules apply, no runtime concerns), `*.ipynb` (ruff lints notebooks; review tolerance for `print` and top-level statements is different), `pyproject.toml`, `uv.lock` / `poetry.lock` / `pdm.lock` / `pylock.toml`, `requirements*.txt`, `setup.py`/`setup.cfg` (legacy), `tox.ini`, `noxfile.py`, `conftest.py`, `py.typed`, `.python-version`.

**The Python version comes from three places, in order of authority.**
1. `[project] requires-python = ">=3.12"` in `pyproject.toml`. The lower bound is the floor the code must run on. The packaging guide says to "think twice before applying an upper bound"; an upper bound (`<3.14`) is itself a review finding unless justified.
2. `.python-version` (uv, pyenv) and the Dockerfile's base image say what is actually run; a CI matrix in `.github/workflows/*.yml` says what is actually tested. If `requires-python` claims 3.11 but CI only runs 3.13, the 3.11 claim is unverified.
3. `[tool.ruff] target-version`, `[tool.mypy] python_version`, `[tool.pyright] pythonVersion`. Ruff infers `target-version` from `requires-python` when unset (`">=3.8"` behaves as `py38`); an explicit value overrides. If the three disagree, say so.

**Tooling config to read before flagging anything** (so the reviewer does not repeat the linter).
- `[tool.ruff.lint] select` / `extend-select` / `ignore` / `per-file-ignores` / `preview`. `select` replaces the default set; `extend-select` adds to it. Ruff's defaults are small (pyflakes plus a handful of pycodestyle rules; the current docs describe it as the correctness/suspicious/complexity/performance/style categories, with security, pedantic and restriction off). If `B`, `S`, `ASYNC`, `DTZ`, `G`, `TRY`, `PT`, `UP` are not selected, the corresponding checklist items are live. `extend-immutable-calls` (`fastapi.Depends`) legitimises `B008` hits. Also check for `# noqa: CODE`, `# ruff: noqa: CODE` and blanket `# noqa` (PGH004) in the diff: a new suppression is itself reviewable.
- `[tool.ruff] target-version`: if older than `requires-python`, ruff's `UP` fixes will not modernise as far as they could.
- `[tool.mypy] strict = true` (enables `disallow-any-generics`, `disallow-subclassing-any`, `disallow-untyped-calls`, `disallow-untyped-defs`, `disallow-incomplete-defs`, `check-untyped-defs`, `disallow-untyped-decorators`, `warn-redundant-casts`, `warn-unused-ignores`, `warn-return-any`, `no-implicit-reexport`, `strict-equality`, `extra-checks`). `warn_unreachable` is **not** in strict; `enable_error_code = ["possibly-undefined", "truthy-bool", "ignore-without-code", "unused-awaitable", "explicit-override", "exhaustive-match", "deprecated"]` are opt-in. The presence of `[[tool.mypy.overrides]] ignore_missing_imports = true` or `follow_imports = skip` means whole packages are `Any`.
- `[tool.pyright] typeCheckingMode = "strict"` or `pyrightconfig.json`. Strict adds the `reportUnknown*` family, `reportMissingParameterType`, `reportMissingTypeArgument`, `reportPrivateUsage`, `reportUnnecessaryIsInstance`/`Cast`/`Comparison`/`Contains`, `reportMatchNotExhaustive`, `reportDeprecated`, `reportUnusedImport`/`Variable`/`Class`/`Function`, `reportUntypedFunctionDecorator`. Still **off even in strict**: `reportImplicitOverride`, `reportMissingSuperCall`, `reportUnnecessaryTypeIgnoreComment`, `reportUnusedCallResult`, `reportImportCycles`, `reportUninitializedInstanceVariable`, `reportCallInDefaultInitializer`, `reportImplicitStringConcatenation`, `reportPropertyTypeMismatch`, `reportUnreachable`. `reportUnusedCoroutine` is an error in both standard and strict.
- `[tool.pytest.ini_options]`: `asyncio_mode = "auto"` or strict; `strict = true` (pytest 9) or `strict_markers`/`xfail_strict`; `addopts = "--import-mode=importlib"`; `filterwarnings = ["error"]` (turns `DeprecationWarning` and "coroutine was never awaited" into failures).
- Formatter: `[tool.ruff.format]` or `[tool.black]`. Never comment on layout, quotes, trailing commas or line length when one is configured.
- Pre-commit / CI: `.pre-commit-config.yaml`, `.github/workflows/*.yml`, `Justfile`/`Makefile`/`noxfile.py` show which of the above actually gate merges. A ruff config that CI does not run enforces nothing.

## 3. Checklist

Format: `- **Rule.** Signal in the diff. Why. [source; ruff code]`.

### 3.1 Idioms and language features

- **No mutable default arguments.** `def f(x, items=[])`, `={}`, `=set()`, or a call `=SomeClass()`/`=time.time()`. The default is evaluated once at definition and shared by every call; the fix is `None` plus `if items is None: items = []`, or an immutable default such as `()`. [Python FAQ "Why are default values shared"; Google 2.12; ruff B006, B008]
- **Closures in loops bind late.** A `lambda` or nested `def` inside `for x in ...` that reads `x` and is called after the loop; all callbacks see the final value. Bind with a default (`lambda n=x: ...`) or `functools.partial`. [Python FAQ "lambdas defined in a loop"; ruff B023]
- **Reuse of a loop or comprehension variable after the loop, or a loop variable shadowing the iterable.** `for i in items: ...` then `i` used below, or `for x in x`. Effective Python item 20 says never use loop variables after the loop ends; `PLW2901` flags rebinding the loop name inside the body. [Effective Python 20; ruff B020, PLW2901]
- **Walrus only where it removes a repeated call.** `(m := re.match(...))` in `if`, `while chunk := f.read(n)`, or reuse inside a comprehension are the intended uses; a `:=` that exists to save one line, or whose evaluation order a reader must think about, should be a statement. PEP 572's own style advice: "prefer statements; they are a clear declaration of intent". [PEP 572; ruff PLW0131 flags a named expression whose value is unused]
- **`match` is for destructuring, not for replacing `if`.** A `match x:` with only literal `case` arms and no capture or class pattern is an `if`/`elif` chain in costume (Effective Python 9). Conversely a `match` over a union or enum without a `case _: assert_never(x)` arm has no exhaustiveness check at runtime or by default in mypy; pyright strict and mypy `exhaustive-match` report it. [Effective Python 9; typing docs `assert_never`; mypy `exhaustive-match`; pyright `reportMatchNotExhaustive`]
- **Keyword-only for booleans and optional behaviour; positional-only for fixed-order arguments.** A new parameter `flag: bool = False` that is not behind `*`, or a call `f(data, True, False)`. Readers cannot tell what `True` means; a later reordering silently changes meaning. Positional-only (`/`) protects names that are implementation details. [Effective Python 37; Google 2.12; ruff FBT001, FBT002, FBT003]
- **No `global` for mutable state; module constants only.** `global counter` inside a function, or a module-level `_cache = {}` mutated from several functions. Google: avoid mutable global state; when unavoidable make it `_private` and expose it through functions. [Google 2.5; Hitchhiker's structure; ruff PLW0603]
- **Do not shadow builtins or stdlib modules.** New names `id`, `type`, `list`, `input`, `hash`, `format`, `object`, or a module file `logging.py`, `types.py`, `queue.py`, `test.py`. The shadow bites far from the definition and a same-named module breaks `import` for the whole package. [ruff A001–A006, A005]
- **`import *` and relative imports.** `from x import *` hides the dependency list and defeats static analysis; Google forbids relative imports and asks for the full package path; the Hitchhiker's guide prefers `import modu` so each name's origin is visible. Flag new wildcard imports always; flag relative imports only if the repo does not already use them consistently (`TID252` is configurable). [Google 2.2, 2.3; Hitchhiker's structure; PEP 8; ruff F403, F405, TID252]
- **Imports at the top; no side effects in `__init__.py`.** `import x` inside a function without a comment explaining the cycle or the lazy cost; an `__init__.py` that runs code, reads config or opens connections. Hitchhiker's calls an empty `__init__.py` "normal and even good practice"; heavy `__init__` slows every import below it. Function-level imports are "fragile hacks" for circular dependencies; the circle is the finding. [Hitchhiker's structure; Google type-annotation section on circular deps; ruff PLC0415, RUF067 (preview)]
- **Executable logic behind `if __name__ == "__main__": main()`.** A module with top-level statements that do work. Modules must import cleanly for tests and `pydoc`. [Google 3.17]
- **Comprehensions: at most one `for` and one `if`; no comprehension for side effects.** `[(x, y) for x in a for y in b if ...]` or `[print(x) for x in xs]`. Google forbids multiple `for` clauses; a comprehension evaluated for its side effects builds and discards a list. [Google 2.7; Hitchhiker's style; Effective Python 41; ruff C4xx for the redundant forms]
- **Prefer `enumerate`, `zip(strict=True)`, direct iteration, `''.join`.** `for i in range(len(xs))`, `zip(a, b)` where lengths must match, `for k in d.keys()`, `s += piece` in a loop. On 3.10+ `zip` without `strict=` silently truncates; `+=` on strings in a loop is quadratic. [Effective Python 17, 18; Google 2.8, 3.10; Hitchhiker's structure; ruff B905, SIM118, PLC0206, FURB113 (preview)]
- **Lambda only as a one-liner; never bound to a name.** `f = lambda x: ...` loses the function's name in tracebacks; `map(lambda ...)`/`filter(lambda ...)` should be a comprehension; `lambda x, y: x * y` should be `operator.mul`. [PEP 8; Google 2.10; Effective Python 39, 40; ruff E731, C417, PLW0108]
- **Explicit string concatenation; beware the missing comma.** Adjacent literals in a list `["a" "b", "c"]` silently join. Effective Python 13 and ruff ISC001/ISC004 both target it; black and the ruff formatter do not fix it. [Effective Python 13; ruff ISC001, ISC004]
- **`@staticmethod` is usually a module function; `@classmethod` is for alternative constructors.** A new `@staticmethod` that touches neither class nor instance. Google: avoid `staticmethod`; use `classmethod` only for named constructors or class-level state. Return `Self` from such constructors. [Google 2.17; Effective Python 52; typing docs `Self`]
- **No power features without a reason.** New metaclasses, `__getattr__` magic, import hooks, `__del__` for cleanup, `exec`/`eval`, bytecode or frame access. Google 2.19 and the Hitchhiker's "avoid the magical wand" both list these; `__del__` is not a reliable finalizer. Standard-library users of these features (`abc`, `dataclasses`, `enum`) are fine. [Google 2.19; Hitchhiker's style; Effective Python 66, 91]
- **`from __future__ import annotations` on a 3.14 floor is a choice, not a default.** On 3.14 annotations are lazily evaluated already; the import keeps the old stringified semantics and changes what `__annotations__` and `TypedDict.__required_keys__` return. Code that reads annotations at runtime (`get_type_hints`, pydantic, dataclass field introspection) should use `annotationlib.get_annotations(fmt=...)` or at least be checked when this import is added or removed. [What's New 3.14; typing docs on `get_type_hints` caveat]
- **t-strings are not strings (3.14).** `t"..."` yields a `string.templatelib.Template`; passing one where a `str` is expected breaks. Conversely, their purpose is sanitising SQL/HTML/shell, so an f-string handed to a sink on 3.14 where a t-string API exists is worth a comment. [What's New 3.14]

### 3.2 Typing

- **Modern syntax on a 3.10+ floor.** `List[int]`, `Dict[str, Any]`, `Optional[X]`, `Union[A, B]`, `typing.Callable`, `Type[C]`, `typing.Text`, `AnyStr` in new code. The typing docs recommend `list[int]`, `X | None`, `collections.abc.Callable`, `type[C]`, `str`; `AnyStr` is deprecated in 3.13 (removal 3.18) in favour of `[T: (str, bytes)]`; `ByteString` is removed in 3.17. [typing docs deprecated-alias table; ruff UP006, UP007, UP035, UP045, UP019]
- **PEP 695 syntax on a 3.12+ floor.** `T = TypeVar("T")` plus `Generic[T]`, or `Alias: TypeAlias = ...`, in new code when `requires-python >= 3.12`. `type X = ...` is lazily evaluated and scoped; `TypeAlias` is deprecated since 3.12. Mixing old and new in one class is an error (`RUF053`). [What's New 3.12; typing docs; ruff UP040, UP046, UP047, RUF053]
- **No bare generics; no `Any` where a `TypeVar` or `object` would do.** `x: list`, `-> dict`, `Sequence` without parameters (treated as `Sequence[Any]`), `def f(x: Any)` for a value only passed through. Google: "always specify type parameters"; mypy `disallow-any-generics` is in `--strict`, pyright strict has `reportMissingTypeArgument`. [Google type annotations; mypy `type-arg`; pyright `reportMissingTypeArgument`; mypy `explicit-any`]
- **Every `# type: ignore` and `cast` must carry a code or a reason.** `# type: ignore` with no `[code]`, `# pyright: ignore` without a rule, `cast(Foo, x)` with no comment. A blanket ignore hides every future error on that line; `cast` "intentionally doesn't check anything" at runtime. mypy `ignore-without-code` and `warn_unused_ignores`, pyright `reportUnnecessaryTypeIgnoreComment` (off even in strict) catch the mechanics; the reviewer asks why. [typing docs `cast`; mypy `ignore-without-code`, `unused-ignore`; pyright config; ruff PGH003]
- **`Optional` must be explicit and checked.** `def f(x: str = None)` (implicit optional, `RUF013`); a parameter typed `X | None` whose `None` branch is never handled; `None` not last in a union (`RUF036`). [ruff RUF013, RUF036; PEP 8 on `is None`]
- **`Self` for fluent and constructor returns; `Never` for the bottom.** `def clone(self) -> "Foo"` on a class that will be subclassed; `-> NoReturn` is fine but `Never` is the 3.11 spelling for exhaustiveness. Do not use `Self` when the method always returns a fixed class. [typing docs `Self`, `Never`]
- **`TypeIs` over `TypeGuard` when the narrowed type is a subtype (3.13).** A new `-> TypeGuard[Foo]` predicate whose `False` branch should also narrow. `TypeIs` narrows both branches to the intersection; `TypeGuard` only the `True` branch. [typing docs; What's New 3.13]
- **`@override` on overriding methods (3.12); `@final` where subclassing must stop.** A subclass method that replaces a base method without `@override`, so a base rename silently orphans it. Neither mypy nor pyright strict requires it by default (`explicit-override`, `reportImplicitOverride` are opt-in), so the reviewer does. [PEP 698 via What's New 3.12; typing docs; mypy `explicit-override`]
- **`Protocol` for duck typing; `@runtime_checkable` only checks presence.** A new ABC whose only purpose is an interface, or `isinstance(x, SomeProtocol)` used to validate a signature. Runtime checks "only verify that attributes are present" and ignore types. [typing docs `Protocol`]
- **`TypedDict` qualifiers instead of `total=False` everywhere; `ReadOnly` (3.13) for immutable keys.** A `TypedDict` where most keys are required but one is optional should use `NotRequired`; introspecting `__total__` is wrong, use `__required_keys__`. `TypedDict` is a `dict` at runtime: no validation happens. [typing docs `TypedDict`]
- **Decorators typed with `ParamSpec`/`Concatenate` and `functools.wraps`.** A decorator returning `Callable[..., Any]` erases the wrapped signature; without `@wraps` the name and docstring are lost. `P.args`/`P.kwargs` only on `*args`/`**kwargs`. [typing docs `ParamSpec`; functools docs `wraps`; Effective Python 38; mypy `untyped-decorator`]
- **Abstract parameter types, concrete return types.** `def f(items: list[int])` where only iteration is needed; prefer `Sequence`/`Iterable`/`Mapping` in signatures (Google). A `Mapping` parameter also documents that the function does not mutate it. [Google type annotations]
- **`Literal`, `Final`, `Enum` for closed sets.** A `str` parameter whose docstring enumerates allowed values should be `Literal[...]` or an `Enum`; a module constant reassigned anywhere should be `Final`. Neither is enforced at runtime. [typing docs `Literal`, `Final`; pyright `reportConstantRedefinition`]
- **Typing-only imports behind `TYPE_CHECKING`, but never evaluated at runtime.** An import used only in annotations that creates a cycle belongs in `if TYPE_CHECKING:`; but a name imported there and then used in `get_type_hints`, a pydantic model, or a `cast` at runtime raises `NameError`. [typing docs `TYPE_CHECKING`; Google conditional imports; ruff TC001–TC004]
- **`reveal_type`, `assert_type` left in committed code.** `reveal_type` prints to stderr at runtime; `assert_type` is harmless but noise. [typing docs]
- **`py.typed` ships with a typed library.** A library that adds annotations but no `py.typed` in the package directory (and in package data) gives consumers nothing; partial coverage must say `partial\n`. [PEP 561]

### 3.3 Nulls, truthiness and equality

- **`is None` / `is not None`, never `== None`.** PEP 8; `E711`. Also `if not foo is None` should be `if foo is not None`. [PEP 8; Google 2.14; ruff E711, E714]
- **`is` only for singletons, never for literals or ints/strs.** `x is 1`, `s is "abc"`, `x is True`. Identity of small ints and interned strings is an implementation accident; the FAQ lists the three cases where `is` is guaranteed (assignment, container membership, `None`). [Python FAQ "identity tests"; ruff F632]
- **Do not compare booleans to `True`/`False`.** `if x == True`, `if flag is True`. Write `if flag:`. [PEP 8; Google 2.14; ruff E712]
- **Truthiness for emptiness, but not when `None` is a distinct value.** `if len(xs) == 0`, `if xs == []` should be `if not xs`; but `if not x` where `x: int | None` and `0` is valid conflates `0`/`""`/`[]` with `None`. PEP 8: "don't write `if x` when you mean `if x is not None`". [PEP 8; Google 2.14; ruff PLC1802, PLC1901 (preview)]
- **`isinstance`, not `type(x) == T`.** `type(x) == Foo` breaks subclasses. If exact type matters, say so in a comment. [PEP 8; ruff E721]
- **Float equality.** `a == b` on floats, `assert result == 0.3`. Use `math.isclose` or `pytest.approx`. [pytest assert docs; ruff RUF069 (preview)]
- **`__eq__` without `__hash__`.** A class defining `__eq__` becomes unhashable (`__hash__ = None`) and silently stops working in sets and dict keys. The dataclass rules are the same: `eq=True, frozen=False` yields unhashable instances. [dataclasses docs; ruff PLW1641]
- **Truthiness of objects without `__bool__`/`__len__`, and of `Iterable`.** `if some_obj:` on a plain class is always true; `if not items:` where `items: Iterable[int]` never consumes it and is always false for a generator. [mypy `truthy-bool`, `truthy-iterable`]
- **Naive vs aware datetimes never mix.** Ordering a naive and an aware `datetime` raises `TypeError`; equality between them is always `False` with no error. A new `datetime.now()` or `datetime(2024, 1, 1)` next to aware values is a latent bug. [datetime docs; ruff DTZ001, DTZ005]
- **`NotImplemented` vs `NotImplementedError`.** `raise NotImplemented` is a `TypeError`; `return NotImplementedError` from a binary dunder is wrong too. Binary operators return `NotImplemented`; abstract methods raise `NotImplementedError`. On 3.14 `NotImplemented` in a boolean context raises `TypeError`. [What's New 3.14; ruff F901]
- **`dict.get(k) or default` when a falsy stored value is valid.** `cfg.get("retries") or 3` turns a stored `0` into `3`. Use `cfg.get("retries", 3)`. [ruff RUF056 (preview), SIM910]
- **Chained comparisons and Yoda conditions.** `if 0 < x and x < 10` should be `0 < x < 10`; `if "a" == x` reads backwards. [ruff PLR1716, SIM300]

### 3.4 Collections and iteration

- **Never mutate a container while iterating it.** `for k in d: del d[k]`, `for x in xs: xs.remove(x)`. `RuntimeError` for dicts and sets, skipped elements for lists. Iterate a copy, build a new container, or collect keys first. [Google 2.8; Effective Python 22; Hitchhiker's style; ruff B909 (preview), PLE4703 (preview)]
- **`[[]] * n` aliases one inner list.** Use `[[] for _ in range(n)]`. [Hitchhiker's style; Python FAQ aliasing]
- **Generators are consumed once.** A generator (or `map`/`filter`/`zip` result, file object) iterated twice, passed to `len()`, or stored and reused; `itertools.groupby` groups reused after the outer loop advances. Materialise with `list()` when a second pass is needed. Effective Python 21 says be defensive when iterating over arguments. [Effective Python 21; ruff B031]
- **`sorted()` returns a new list; `.sort()` returns `None`.** `xs = xs.sort()`, `return items.sort()`. Likewise `.reverse()`, `.append()`, `dict.update()`. [Effective Python 101]
- **`copy` vs `deepcopy`; aliasing on assignment.** `b = a` then mutating `b` changes `a`; `copy.copy` of a nested structure shares the inner lists. The FAQ's "Why did changing list y also change list x". [Python FAQ]
- **Dict ordering is insertion order; do not rely on it for semantics across serialisation boundaries.** Code that depends on `dict` order after a JSON round trip or a database read; Effective Python 25 warns about relying on insertion ordering when the dict-like object may not be a `dict`. [Effective Python 25]
- **Membership tests on the right structure.** `x in some_list` inside a loop over a large list; `k in d.keys()`. A set or dict lookup is O(1); `in d` is the idiom. [Hitchhiker's style; ruff SIM118, PLR6201 (preview)]
- **`dict.get`/`defaultdict`/`setdefault` for missing keys; `try/except KeyError` only when the key is usually present.** `if k in d: v = d[k] else: ...` chains. [Effective Python 26, 27; ruff SIM401, RUF019]
- **Default-constructed `datetime.min`/`max` comparisons, `sum()` over lists, `list(...)[0]`.** `sum(lists, [])` is quadratic; `next(iter(xs))` instead of `list(xs)[0]`. [ruff RUF017, RUF015, DTZ901]
- **Pass iterators to `any`/`all`, not lists.** `all([f(x) for x in xs])` evaluates everything; the generator form short-circuits. [Effective Python 23; ruff C419]
- **`itertools` instead of hand-rolled loops; `batched` (3.12), `pairwise` (3.10).** `zip(xs, xs[1:])` is `pairwise`; manual chunking is `batched` (which also takes `strict=` from 3.13, `B911`). [What's New 3.12; Effective Python 24; ruff RUF007, B911]
- **Unpacking over indexing.** `x = t[0]; y = t[1]`; `first = xs[0]; rest = xs[1:]`. Catch-all unpacking `first, *rest = xs` is clearer and fails loudly on wrong lengths. [Effective Python 5, 16; Hitchhiker's style]

### 3.5 Error handling and resources

- **No bare `except:` and no `except Exception: pass`.** Bare `except` also catches `SystemExit`, `KeyboardInterrupt` and (in asyncio) `CancelledError`; `except Exception: pass` turns every bug into silence. Acceptable only when re-raising or logging the traceback at an isolation boundary. [PEP 8; Google 2.4; Effective Python 85, 86; ruff E722, BLE001, S110, S112]
- **Catch the narrowest exception; keep the `try` body minimal.** A `try` wrapping twenty lines so that an unrelated `KeyError` is caught by the handler meant for I/O. PEP 8 and Effective Python 83 both say the smallest possible `try`. [PEP 8; Effective Python 83; ruff PLW0717 (preview), TRY301]
- **`raise ... from err` (or `from None`) inside an `except`.** A new exception raised in a handler without `from` gets an implicit `__context__` with the misleading "During handling of the above exception, another exception occurred"; `from err` says "direct cause"; `from None` deliberately suppresses. [PEP 3134; PEP 8; Effective Python 88; ruff B904, TRY200]
- **Do not `raise` a bare `Exception` or a class with a long literal message; build a hierarchy.** `raise Exception("...")`, `raise ValueError(f"long {msg} ...")` repeated across a module. A root exception per package (Effective Python 121) lets callers distinguish, and `EM101`/`EM102` ask for the message in a variable so the traceback reads cleanly. [PEP 8 exception hierarchies; Effective Python 121; ruff TRY002, TRY003, EM101, EM102]
- **`assert` is not validation.** `assert user is not None`, `assert isinstance(x, int)` on input; stripped under `-O`. Raise `ValueError`/`TypeError`. Tests are the exception (`S101` is normally ignored under `tests/`). An `assert` on a tuple is always true (`F631`); an `assert` with a side-effecting assignment is skipped under `-O` (`RUF018`). [Google 2.4; Effective Python 81; ruff S101, F631, RUF018, B011]
- **`with` for every resource; `contextlib.closing` for the rest.** `f = open(...)` without `with`, a socket, a `requests.Session`, a DB cursor, a `subprocess.Popen`, a `tempfile` left to the garbage collector; `open()` inside a generator whose consumer may stop early (Effective Python 89). [PEP 8; Google 3.11; Hitchhiker's style; ruff SIM115]
- **No `return`/`break`/`continue` leaving a `finally`.** It silently discards the in-flight exception; a `SyntaxWarning` on 3.14. [PEP 8; What's New 3.14 (PEP 765); ruff B012, PLE0116]
- **`try` ... `else`.** Code after the risky call inside the `try` that cannot raise the caught exception belongs in `else`, so a success path is not confused with the failure it handles. [Effective Python 80; ruff TRY300]
- **`except` that only re-raises, or that logs and re-raises at every level.** `except E: raise` is a no-op; `except E as e: logger.error(e); raise` repeated at each frame logs the same failure three times. Log at the boundary that handles it. [ruff TRY203, TRY201, TRY400]
- **Handlers that catch the right thing: no duplicate or redundant tuples, no non-exception classes.** `except (ValueError, ValueError)`, `except (OSError, IOError)` (aliases since 3.3), `except ()`. [ruff B013, B014, B025, B029, B030, UP024]
- **`sys.exit()`, `os._exit()`, `print()` in library code.** A library should raise; the application decides the exit code. `print` belongs in CLIs; libraries use `logging` or `warnings`. [logging HOWTO "when to use logging"; ruff T201, PLR1722]
- **`ExceptionGroup` handling (3.11).** Code awaiting a `TaskGroup` or anyio task group that catches `except ValueError:` never fires because the group raises `ExceptionGroup`; use `except*` or `RaisesGroup` in tests. [asyncio-task docs; anyio tasks; pytest assert docs]
- **Deprecation goes through `warnings`, not `logging`.** A deprecated function that `logger.warning(...)`s; the HOWTO says `warnings.warn` for avoidable client issues. Use `warnings.warn(msg, DeprecationWarning, stacklevel=2)` so it points at the caller, or `@warnings.deprecated` (3.13) so type checkers see it too. `DeprecationWarning` is ignored by default outside `__main__`, so the tests must enable it (`filterwarnings = error`). [warnings docs; logging HOWTO; ruff B028]
- **Return consistency and `None` vs raise.** A function with `return value` on one path and a bare `return` (or fall-through) on another; a lookup that returns `None` to mean "not found" when `None` is also a valid value. Effective Python 32: prefer raising to returning `None`. [PEP 8; Effective Python 32; ruff RET501–RET503]

### 3.6 Concurrency and async

- **Keep a reference to every `asyncio.create_task` result.** `asyncio.create_task(coro())` as a bare statement. "The event loop only keeps weak references to tasks. A task that isn't referenced elsewhere may get garbage collected at any time, even before it's done." Prefer `TaskGroup`; otherwise store in a set with a done callback. [asyncio-task docs; ruff RUF006; mypy `unused-awaitable`]
- **`TaskGroup` (3.11) over bare `gather` for structured concurrency.** `asyncio.gather(*coros)` without `return_exceptions`: the first exception propagates and "other awaitables won't be cancelled" and keep running orphaned; with `return_exceptions=True` the caller must inspect every result for exception instances and usually does not. `TaskGroup` cancels siblings and raises an `ExceptionGroup`. [asyncio-task docs; anyio tasks]
- **Coroutine never awaited.** `some_async_fn()` as a statement or assigned without `await`/`create_task`; the runtime only warns (`RuntimeWarning: coroutine ... was never awaited`) and only at GC. pyright reports it as an error in every mode. [asyncio-dev docs; pyright `reportUnusedCoroutine`; ruff PLE1142 for `await` outside async]
- **No blocking calls in coroutines.** `time.sleep`, `requests.get`, `open().read()`, `subprocess.run`, `input()`, `Path.read_text`, a sync DB driver, CPU-bound loops, inside `async def`. A one-second block delays every task. Use `await asyncio.sleep`, `httpx.AsyncClient`, `aiofiles`, `asyncio.create_subprocess_exec`, or `await loop.run_in_executor(None, fn)` / `asyncio.to_thread`. [asyncio-dev docs "running blocking code"; ruff ASYNC210, ASYNC220–ASYNC222, ASYNC230, ASYNC240, ASYNC251]
- **Re-raise `CancelledError`.** `except asyncio.CancelledError: return` or `except BaseException:` that swallows it; `TaskGroup` and `timeout()` "might misbehave if a coroutine swallows `CancelledError`". Cleanup goes in `finally` or re-raises after. Since 3.8 it is a `BaseException`, so `except Exception:` does not catch it; a bare `except:` does. [asyncio-exceptions docs; asyncio-task docs]
- **Timeouts via `asyncio.timeout()` (3.11) around the await, and catch `TimeoutError` outside the block.** `wait_for` is fine but can wait longer than the timeout; an `async def f(timeout: float)` parameter that re-implements a deadline is `ASYNC109`. `asyncio.TimeoutError` is a deprecated alias of the builtin since 3.11. [asyncio-task docs; asyncio-exceptions docs; ruff ASYNC109, UP041]
- **Nested `asyncio.run`, `get_event_loop()` from sync code, `loop=` arguments.** `asyncio.run` inside a running loop raises; `get_event_loop()` without a running loop warns on 3.12 and the policy system is deprecated in 3.14; `loop=` parameters were removed in 3.10. [What's New 3.12; asyncio-sync docs]
- **asyncio primitives are not thread-safe; threads talk to the loop through `call_soon_threadsafe`/`run_coroutine_threadsafe`.** An `asyncio.Lock` shared with a `threading.Thread`, a `Future.set_result` from another thread, a `queue.Queue` awaited in a coroutine. [asyncio-dev docs; asyncio-sync docs]
- **Busy-wait and zero-sleep loops.** `while not done: await asyncio.sleep(0)` or `sleep(0.01)` polling; use an `Event`, `Condition` or `Queue`. `sleep(0)` is only for yielding inside a long CPU section. [asyncio-task docs; ruff ASYNC110, ASYNC115, ASYNC116]
- **Async generators must be closed and not shared.** `async for` with `break` and no `aclosing()`; a generator created before the loop starts; one generator iterated by two tasks (`RuntimeError: anext(): asynchronous generator is already running`). [asyncio-dev docs; ruff ASYNC119 (preview)]
- **`async def` with no `await` is a sync function in disguise, or missing an await.** [ruff RUF029 (preview)]
- **Threads: do not rely on atomicity of builtins, especially with free-threading (3.13t/3.14t).** `counter += 1`, check-then-act on a dict, `list.remove` concurrently, or iterating a shared iterator from two threads. The free-threading HOWTO: "It's recommended to use the `threading.Lock` or other synchronization primitives instead of relying on the internal locks of built-in types"; PEP 703: per-object locks "provide weaker protections than the GIL". Google 2.18: use `queue.Queue` and `threading.Condition`. `cached_property` dropped its lock in 3.12 and may run the getter twice. [Google 2.18; PEP 703; free-threading HOWTO; functools docs; Effective Python 69, 70]
- **`multiprocessing` start method and `fork` after threads.** Code relying on `fork` semantics (inherited globals, unpicklable objects) breaks on 3.14 where `forkserver` is the Unix default; `os.fork()` from a multithreaded process warns from 3.12. Set the start method explicitly. [What's New 3.12, 3.14]
- **Eager task factory and ordering assumptions.** Tests or code that assume `create_task` does not start the coroutine until the next loop iteration break under `eager_task_factory` (3.12) or `eager_start=True`. [asyncio-task docs]

### 3.7 Security

- **No `pickle`/`marshal`/`shelve`/`yaml.load` on untrusted data.** `pickle.loads(request.data)`, `yaml.load(s)` or `Loader=yaml.Loader`/`FullLoader` on external input. "The pickle module is not secure"; "`yaml.load` is as powerful as `pickle.load`". Use `json`, `yaml.safe_load`, or sign with `hmac`. [pickle docs; PyYAML docs; security_warnings page; ruff S301, S302, S506; bandit B301, B506]
- **No `eval`/`exec` on input; `ast.literal_eval` for literals.** Also `logging.config.listen`/`fileConfig` use `eval` on their input. [Effective Python 91; security_warnings page; ruff S102, S307, S612]
- **`subprocess` with a list, `shell=False`, `check=`, `timeout=`.** `subprocess.run(f"cmd {arg}", shell=True)`, `os.system`, `os.popen`; a `Popen` without `communicate(timeout=)`. With `shell=True` "it is the application's responsibility to ensure that all whitespace and metacharacters are quoted" (`shlex.quote`). Also `PLW1510` for `run` without `check`. [subprocess docs; ruff S602–S607, PLW1510, PLW1509]
- **SQL through parameters, never through string formatting.** `cursor.execute(f"... WHERE id = {x}")`, `"..." % x`, `.format`, `+`. "Beware of using Python's string operations to assemble queries". Identifiers (table/column names) cannot be parameters: allow-list them. [sqlite3 docs; ruff S608; bandit B608, B610, B611]
- **`secrets`, not `random`, for tokens, salts, session ids, nonces; constant-time comparison.** `random.choice` for a password, `uuid4` for a security token is acceptable but `random.random()` is not; `token == expected` with `==` on a secret should be `secrets.compare_digest`. [secrets docs; ruff S311; bandit B311]
- **Passwords with Argon2id/scrypt/bcrypt, never `hashlib.sha256`/`md5`.** `hashlib.sha256(password.encode())`. OWASP: "fast hashing algorithms such as SHA-256 are not suitable for password storage"; Argon2id m=19 MiB, t=2, p=1; PBKDF2-HMAC-SHA256 600 000 iterations only when FIPS is required. `md5`/`sha1` elsewhere should pass `usedforsecurity=False`. [OWASP Password Storage; security_warnings page; ruff S324, S303; bandit B324]
- **`tarfile.extractall(filter="data")` and zip-slip checks.** `extractall()` with no `filter` on a floor below 3.14 honours absolute paths and `..` links; on 3.12/3.13 it warns, on 3.14 `data` is the default. The docs still say "never extract archives from untrusted sources without prior inspection" and list extra limits (file count, total size, symlinks). `zipfile` has no filter: check each `name` against the destination. [tarfile docs; What's New 3.12; ruff S202; bandit B202]
- **XML from untrusted sources through a hardened parser.** `xml.etree.ElementTree.fromstring(untrusted)`, `minidom`, `sax`, `xmlrpc`: billion laughs, quadratic blowup, decompression bombs; protection depends on the Expat version linked in. Use `defusedxml` or verify `pyexpat.EXPAT_VERSION`. [xml docs; ruff S313–S320; bandit B313–B320]
- **`tempfile.mktemp` and hard-coded `/tmp` paths.** Race condition; use `NamedTemporaryFile`, `TemporaryDirectory`, `mkstemp`. Files are created owner-only. [tempfile docs; security_warnings page; ruff S306, S108]
- **`requests`/`httpx` with a timeout, with verification, without user-controlled URLs.** `requests.get(url)` with no `timeout=` ("by default, requests do not time out"); `verify=False` ("vulnerable to man-in-the-middle"); a URL built from user input (SSRF: allow-list hosts, resolve and check the IP, disable redirects). [requests docs; OWASP SSRF; ruff S113, S501; bandit B113, B501]
- **Templates with autoescaping; no `Markup`/`mark_safe` on user data.** `jinja2.Environment()` without `autoescape=select_autoescape()` ("autoescaping is off by default"); `Markup(user_string)`, Django `mark_safe`. [Jinja API docs; ruff S701, S704, S308; bandit B701, B703, B704]
- **No secrets in code, logs or defaults.** `password="..."`, `api_key = "sk-..."`, a default argument holding a credential, a connection string with a password logged at startup. OWASP logging: never log passwords, session ids, access tokens, keys, card data, health or government identifiers. [OWASP Logging; ruff S105–S107; bandit B105–B107]
- **Binding to `0.0.0.0`, `debug=True`, insecure TLS versions, missing host-key verification.** [ruff S104, S201, S502–S504, S507]
- **`assert` for access control.** Stripped under `-O` (see 3.5). [ruff S101]
- **Path traversal.** `open(base / user_supplied)` without resolving and checking `.is_relative_to(base)`; `Path(user_input)` with `..`. (General OWASP principle; the tarfile docs list the same checks for archive members.) [tarfile docs "additional checks"]

### 3.8 Classes, dataclasses and API design

- **Mutable class attributes are shared across instances.** `class C: items: list[int] = []` or `cache = {}` in a class body (not under `ClassVar`), and in a dataclass a mutable default raises `ValueError` at class creation unless `field(default_factory=...)` is used. [dataclasses docs; ruff RUF012, RUF008, RUF009]
- **Dataclass hygiene.** `frozen=True` for value objects (hashable only when `eq` and `frozen` are both true); `slots=True` on 3.10+ for many-instance types (returns a new class, incompatible with existing `__slots__`, and base-class `super()` without arguments is affected per attrs' note); `kw_only=True` for wide constructors; `order=True` only if ordering is meaningful; a field without a default after one with a default is a `TypeError`, including through inheritance; `__post_init__` is not called when `init=False`; `replace()` skips `init=False` fields. A dataclass that is also an `Enum` is wrong (`RUF049`). [dataclasses docs; Effective Python 51, 56; ruff RUF033, RUF045, RUF049]
- **dataclass vs attrs vs pydantic.** Pydantic is "first and foremost a data validation & type coercion library": use it at the boundary where untrusted input is parsed, not for every internal domain object ("is it really necessary to re-validate all your objects while reading them from a trusted database?"). `attrs` when validators/converters are wanted without pydantic's cost. A `NamedTuple` for a record that should not be iterable or indexable is a smell. [attrs "Why"; Effective Python 29, 31]
- **`super().__init__()` in subclasses; `__init__` returning a value.** A subclass `__init__` that forgets `super().__init__(...)`; a generated dataclass `__init__` does not call the base `__init__` either (call it from `__post_init__`). pyright's `reportMissingSuperCall` is off even in strict. [dataclasses docs; Effective Python 53; ruff PLE0101]
- **Properties are cheap and side-effect free.** `@property` that does I/O, a network call, or mutates state; a setter/getter pair that only wraps an attribute (make it public). PEP 8: "avoid using properties for computationally expensive operations; the attribute notation makes the caller believe that access is (relatively) cheap." A `@property` with parameters is a method. [PEP 8; Google 2.13, 3.15; Effective Python 58, 59; ruff PLR0206]
- **`lru_cache`/`cache` on methods leaks instances; `cache` is unbounded.** `@functools.cache` or `@lru_cache` on an instance method keeps every `self` alive until eviction; `cache`/`lru_cache(maxsize=None)` never evicts. Use `cached_property` for per-instance no-argument values, or cache on a module function keyed by the relevant attributes. Never cache impure functions. [functools docs; Python FAQ "cache method calls"; ruff B019]
- **Public surface is deliberate: `_private`, `__all__`, no reliance on imported names.** New public names with no docstring; a module-level helper imported by another module via the first module (treat imported names as implementation details); `__all__` out of date or unsorted; private member access `obj._x` from another module. PEP 8: "if in doubt, choose non-public". [PEP 8 naming; Google 3.16; Effective Python 55, 119; ruff SLF001, RUF022, PLE0604, PLE0605, F822]
- **`Enum`/`StrEnum` (3.11) over string constants; no duplicate values; `.value` leaks.** Module constants `STATUS_OPEN = "open"` used as a set; a `str, Enum` mixin on 3.11+ should be `StrEnum`; two members with the same value silently alias (`PIE796`). [What's New 3.11 via typing/UP042; ruff UP042, PIE796]
- **Exceptions named `...Error`, derived from `Exception`, one root per package.** [PEP 8; Effective Python 121; ruff N818]
- **`__repr__` for debuggability; `__eq__` with `__hash__`; `total_ordering` or all six.** A domain class with no `__repr__` prints as `<Foo object at 0x...>` in every log and test failure. [PEP 8 rich comparisons; functools docs; Effective Python 12; ruff PLW1641]
- **Boolean trap and long signatures.** More than about five positional parameters, or any positional `bool` (see 3.1). [ruff PLR0913, PLR0917, FBT001]
- **`__slots__` correctness.** `__slots__ = "name"` (a string, not a tuple) creates one slot named `n`,`a`... no: it creates one slot `"name"` but is a common mistake flagged by `PLC0205`; assigning an attribute not in `__slots__` is `PLE0237`. [ruff PLC0205, PLE0237, RUF023]
- **Abstract base classes with no abstract methods, and empty methods without `@abstractmethod`.** [ruff B024, B027]
- **Deprecation path for API changes.** A renamed or removed public function with no `@deprecated`/`warnings.warn` shim and no changelog entry; a changed default argument value. [warnings docs; Effective Python 123]
- **Docstring contract (PEP 257) for public callables.** Summary line in the imperative ("Return ...", not "Returns ..."), ends in a period; documents `Args`/`Returns`/`Raises` or the project's convention; `Yields` for generators; the class docstring describes the instance, `__init__` documents construction. Do not comment on docstring punctuation if ruff `D` is selected with a convention. [PEP 257; Google 3.8, 2.9; ruff D401, D417, D205, D400; DOC5xx (preview) for undocumented raises]

### 3.9 Logging and observability

- **Lazy `%s` formatting, not f-strings or `%` at the call site.** `logger.info(f"user {u}")`, `logger.info("user %s" % u)`, `logger.info("user " + u)`. The `%` merge happens in `Formatter.format()` only if the record passes the level; an f-string also breaks aggregation by message template. [logging docs; Google 3.10.1; ruff G001–G004]
- **`logging.getLogger(__name__)` per module; never the root logger; never `print`.** `logging.info(...)` on the module (root logger), `logging.getLogger()` with no name, `logger = logging.Logger("x")` (bypasses the hierarchy). [logging docs; logging HOWTO; ruff LOG001, LOG015, T201]
- **Libraries add only a `NullHandler`, never `basicConfig`, handlers or levels.** A library module calling `logging.basicConfig`, adding a `StreamHandler`, or setting a level on its logger. "Configuration of handlers is the prerogative of the application developer." [logging HOWTO]
- **`logger.exception(...)` in handlers; `exc_info` only inside an `except`.** `logger.error(str(e))` in an `except` drops the traceback; `logger.error(..., exc_info=True)` outside a handler attaches nothing; `logger.exception(e)` passes the exception as the message (`TRY401` redundant). [logging docs; ruff TRY400, LOG004, LOG007, LOG014, G201, G202, TRY401]
- **`logger.warn` is deprecated; `warning`.** [ruff G010]
- **No secrets or PII in log calls; structured fields via `extra=`.** A log line interpolating a token, password, `Authorization` header, card number, or a full request body; untrusted strings with CR/LF reaching an unstructured log (log injection). Prefer `extra={...}` or a structured logger; keys in `extra` must not clash with `LogRecord` attributes (`G101`). [OWASP Logging; logging docs `extra`; ruff G101]
- **Format-string argument mismatch.** `logger.info("%s %s", a)` raises at emission time, which is to say in production under the error path. [ruff PLE1205, PLE1206]
- **Right level, right tool.** `print` for CLI output; `warnings.warn` for a fixable misuse by the client; `logger.warning` for an unfixable notable event; raise for errors. Log in an `except` that swallows the error, not before re-raising. [logging HOWTO table]
- **`stacklevel` on helper-wrapped logging and warnings.** A logging or warning wrapper without `stacklevel=2` attributes every record to the wrapper. [logging docs `stacklevel`; warnings docs; ruff B028]
- **Blocking handlers in async code.** A network `SocketHandler`/`HTTPHandler` on the loop thread blocks the loop; use `QueueHandler` with a listener thread. [asyncio-dev docs "logging"]

### 3.10 Tests

- **pytest style: plain `assert`, `pytest.raises` as a context manager with `match=`, minimal block.** `self.assertEqual`, `pytest.raises(Exc, fn, *args)` (legacy form), `with pytest.raises(Exception):` (too broad), `pytest.raises(ValueError)` with no `match=` when the message is the contract, several statements inside the `with` so an earlier line could raise the expected type by accident. `match` uses `re.search`. [pytest assert docs; ruff PT009, PT011, PT012, PT027, RUF061, B017]
- **Patch where the object is looked up.** `patch("requests.get")` when the module under test did `from requests import get`; `monkeypatch.setattr(os, "getcwd", ...)` when the code imported `getcwd` directly. "You patch where an object is looked up, which is not necessarily the same place as where it is defined." [unittest.mock docs; pytest monkeypatch docs]
- **`autospec=True`/`spec_set`, and no misspelt assertions.** A `Mock()` without a spec accepts any attribute and any signature, so a renamed method keeps the test green; `mock.assert_called_once()` typos outside the guarded prefixes (`assert`, `assret`, `asert`, `aseert`, `assrt`) silently pass. `PGH005` catches `mock.called_once_with(...)` without `assert_`. Over-mocking (mocking the unit under test's own collaborators three levels deep) tests the mocks; Effective Python 109 prefers integration tests. [unittest.mock docs; Effective Python 109, 111, 112; ruff PGH005]
- **Fixture scope and shared mutable state.** A `scope="module"`/`"session"` fixture returning a mutable object that tests mutate; an `autouse=True` fixture with hidden side effects; a fixture doing two state changes with one teardown (if the second raises, the first leaks). Pytest: "keep higher-scope fixtures free of mutable state", "one state-changing action per fixture". [pytest fixtures docs; ruff PT003, PT019–PT022, PT025]
- **`tmp_path`, `monkeypatch`, `caplog`, `capsys` instead of hand-rolled equivalents.** `tempfile.mkdtemp()` in a test without cleanup; `os.environ["X"] = ...` without restore; `sys.path.insert`; `unittest.mock.patch.dict(os.environ)` when `monkeypatch.setenv` is available and undone automatically. [pytest monkeypatch docs; pytest fixtures docs]
- **Parametrize, do not copy-paste; names as a tuple, values as a list; unique cases.** Five near-identical test functions; `@pytest.mark.parametrize("a,b", ...)` with a wrong type for names/values; duplicate parameter sets. [ruff PT006, PT007, PT014]
- **Async tests under a declared mode.** `async def test_x()` without `@pytest.mark.asyncio` in strict mode is silently skipped or collected as a coroutine never awaited; an `async` fixture under `@pytest.fixture` in strict mode is not awaited (needs `@pytest_asyncio.fixture`); mixed `loop_scope` among neighbours is discouraged. If `asyncio_mode = "auto"` is set, none of this applies. [pytest-asyncio concepts; ruff PT024]
- **`xfail` with `reason=` and `strict=True`; `skip` with `reason=`.** A bare `@pytest.mark.xfail` that passes (XPASS) is not a failure unless `strict`; `xfail(raises=...)` pins the expected exception; `run=False` for crashers; `skipif(condition, reason=...)`. `importorskip` for optional dependencies. [pytest skipping docs]
- **Time, randomness and network are controlled.** `datetime.now()`/`time.time()` compared in a test, `random` without a seed, a real HTTP call. Freeze time (freezegun / time-machine) or inject a clock; use `hypothesis` with `assume`/`.filter()` for property tests, and keep its examples deterministic (`max_examples`). [pytest fixtures docs; hypothesis quickstart; Effective Python 112]
- **Float asserts with `pytest.approx`.** `assert total == 0.3`. [pytest assert docs]
- **Test naming and layout.** Files `test_*.py`/`*_test.py`, functions `test_*`, classes `Test*` without `__init__`; a test the collector does not pick up passes vacuously. A `tests/` directory beside `src/` with `--import-mode=importlib`, not `__init__.py`-less duplicates of file names under `prepend` mode. `conftest.py` for shared fixtures, not imported fixture modules (discouraged, may break). [pytest goodpractices; pytest fixtures docs; ruff INP001]
- **Slow and integration tests are marked and skippable; `strict_markers` on.** `@pytest.mark.slow` without registration (a typo creates a new mark silently unless `strict_markers`). [pytest goodpractices strict mode]
- **Assertions that cannot fail.** `assert True`, `assert "msg"` (always true), `assert x` where `x` is a non-empty tuple, `pytest.fail()` with no message, assertions inside `except` that never runs, composite `assert a and b` (hides which half failed). [ruff PT015, PT016, PT017, PT018, PLW0129, F631]
- **Tests expect `DeprecationWarning`s to be visible.** `filterwarnings = ["error"]` in `pytest.ini_options`, or at least `default::DeprecationWarning`; otherwise `utcnow()`, unfiltered `extractall()` and "coroutine was never awaited" pass silently. [warnings docs defaults; pytest goodpractices]

### 3.11 Packaging and dependencies

- **`pyproject.toml` (PEP 621) with `[build-system]`; no new `setup.py`/`setup.cfg` logic.** A diff adding install-time logic to `setup.py`, or metadata split between `setup.cfg` and `pyproject.toml`. "`[build-system]` is strongly recommended". `distutils` is gone in 3.12. [packaging guide writing-pyproject-toml; What's New 3.12]
- **`requires-python` is a floor and matches the code.** Missing, or with an upper bound (`<3.13`) without justification ("think twice before applying an upper bound"); a floor of 3.9 in a project using `match` or `X | Y` at runtime; a floor raised in the diff without a changelog or major-version note. [packaging guide; ruff UP036 for dead version blocks]
- **Libraries declare ranges; applications pin through a lockfile.** `dependencies = ["requests==2.31.0"]` in a library ("not considered best practice to use install_requires to pin"); an application with no `uv.lock`/`poetry.lock`/`pylock.toml` committed, or a lockfile edited by hand (uv: "should be checked into version control", "should not be edited manually"). Upper caps `<3` on every library dependency are a known source of resolution pain and deserve a reason. [packaging install-requires-vs-requirements; uv layout docs]
- **Lockfile and manifest change together.** A `pyproject.toml` dependency change without the matching `uv.lock` change, or vice versa (`uv lock --check` / `uv sync --locked` in CI catches it). A `requirements.txt` regenerated with unrelated churn obscures the real change. [uv layout docs]
- **Optional dependencies and dependency groups.** Dev tools (`pytest`, `ruff`, `mypy`) in `dependencies` rather than `[dependency-groups] dev` (PEP 735) or an extra; an `all` extra that copies lists instead of referencing other extras (drifts). [packaging guide]
- **src layout, importable only when installed.** A flat layout where tests import the working-copy package and shadow the installed one; files like `noxfile.py` and `README.md` importable in editable installs. The src layout avoids three documented failure modes. [packaging src-layout discussion; pytest goodpractices]
- **One source for the version.** `__version__ = "1.2.3"` in `__init__.py` and `version = "1.2.3"` in `pyproject.toml` both edited by hand; prefer `dynamic = ["version"]` with the backend reading one place, or a VCS-derived version, plus a test that `pkg.__version__ == importlib.metadata.version("dist")`. [packaging single-source-version]
- **Entry points over `__main__` hacks.** A console script implemented as `python -m pkg.cli` instructions when `[project.scripts]` would install a command. [packaging guide]
- **License as an SPDX expression (PEP 639); classifiers do not restrict installs.** `license = {text = "..."}` table form is deprecated; a `Programming Language :: Python :: 3.9` classifier is not a `requires-python`. [packaging guide]
- **Private dependencies and indexes do not leak.** A `--index-url` with credentials in `requirements.txt`, a `[[tool.uv.index]]` pointing at an internal host in a public repo, a git+ssh dependency on a private repo in a published library's metadata. [requests docs warning on credentials in env/files, general principle; packaging install-requires-vs-requirements on concrete index options belonging in requirements, not metadata]
- **Typed libraries ship `py.typed` and include it in the wheel.** See 3.2. [PEP 561]
- **Removed and deprecated stdlib.** New imports of `cgi`, `telnetlib`, `crypt`, `pipes`, `imghdr`, `asyncore`, `asynchat`, `imp`, `distutils`, `pkg_resources` (gone from default venvs in 3.12), `lib2to3`; `ast.Num`/`ast.Str` (removed 3.14); `sre_*` modules (3.15). [What's New 3.12, 3.13]
- **`.python-version`, Dockerfile base image and CI matrix agree with `requires-python`.** See section 2.

## 4. Severity hints

**Blocking (correctness or security defect, merge should wait).**
- `pickle`/`yaml.load`/`eval`/`exec`/`marshal` on untrusted input; SQL or shell built from strings; `shell=True` with interpolated input; `verify=False`; `tarfile.extractall` without a filter below 3.14 on external archives; `random` for secrets; fast hashes for passwords; hard-coded credentials; secrets or PII in logs; path traversal; SSRF with user URLs.
- Mutable default argument that is mutated; late-binding closure in a loop; mutating a container while iterating it; mutable class attribute mutated per instance.
- `asyncio.create_task` result dropped; coroutine never awaited; `CancelledError` swallowed; blocking call in a coroutine on a hot path; `gather` whose exceptions are not inspected.
- Bare `except:` / `except Exception: pass` that hides errors; `raise` in `except` without `from` when the original is needed to diagnose; `return`/`break` in `finally`; `assert` used for validation or access control.
- `__eq__` without `__hash__` on a type used in sets or as a key; naive and aware datetimes compared or subtracted; `utcnow()` in new code (deprecated and naive).
- `lru_cache`/`cache` on instance methods of many-instance classes (memory leak); `cache` on an impure function.
- A patch target that does not affect the code under test (the test passes while the behaviour is untested); a test that cannot fail; an async test silently not run.
- Library code that configures logging handlers, calls `sys.exit`, or `print`s.
- Dependency manifest and lockfile out of step; a library pinning exact versions; `requires-python` that the code violates.

**Should fix (will bite later, or weakens the contract; fix before or soon after merge).**
- Broad `except Exception` at non-boundary code; `try` bodies far larger than the risky call; missing `else`; redundant re-raise/log-and-raise at every level; exception messages inlined (EM); no package root exception.
- `is` with literals; `== None`/`== True`; `type(x) == T`; float `==`; `len(x) == 0`; truthiness of `Optional[int]`.
- Missing `@override`; `# type: ignore` without code; `Any` where a `TypeVar` fits; bare generics; `Optional` implicit; typed library without `py.typed`; `TypeGuard` where `TypeIs` is meant.
- f-strings in logging; root logger use; `logger.error` in `except` instead of `exception`; `warnings` vs `logging` confusion; missing `stacklevel`.
- Positional booleans; `@staticmethod` that should be a function; `@property` doing I/O; dataclass without `frozen`/`slots` where it is a value object; pydantic models for trusted internal data; missing `super().__init__`; missing `__repr__`.
- Session-scoped mutable fixtures; `xfail` without `strict`; `pytest.raises` without `match` or too broad; mocks without `autospec`; time/network not controlled.
- `zip` without `strict`; `range(len(xs))`; `[[]] * n`; generator consumed twice; `sorted` vs `.sort()` confusion; `sum(lists, [])`.
- Threads relying on builtin atomicity (a correctness bug on free-threaded builds, a latent one otherwise); `cached_property` assumed to run once.
- Flat layout for a new package; dev tools in runtime `dependencies`; version duplicated by hand; upper bound on `requires-python`.
- Deprecated stdlib/typing aliases in new code when the floor allows the replacement.

**Nit (mention once, do not block).**
- Comprehension with two `for` clauses that is still readable; `lambda` vs `operator`; walrus taste; `match` vs `if` for a small literal set; `Literal` vs `Enum` choice.
- Docstring mood or punctuation when ruff `D` is not configured; `TODO` without a tracker link; `__all__` unsorted; naming case for an acronym.
- `enumerate` vs manual counter in a three-line loop; `pathlib` vs `os.path` in otherwise consistent `os.path` code (consistency wins per Google's parting words).
- `from __future__ import annotations` kept on a 3.14 floor without runtime introspection.
- Relative imports in a repo that uses them consistently.

## 6. Open questions / disagreements

- **Ruff's default rule set.** The current linter page describes defaults as the correctness/suspicious/complexity/performance/style *categories* (a preview feature); historically the default was `E4`, `E7`, `E9`, `F`. This document did not fetch the "Default Rules" anchor; treat "ruff is configured" as meaning nothing beyond pyflakes unless `select`/`extend-select` names the groups.
- **`except Exception` at boundaries.** PEP 8 and Google permit a broad catch at an isolation point that logs the traceback and continues (a request handler, a worker loop). `BLE001` flags all of them. The reviewer should accept a broad catch that logs with `exception()` and either re-raises or is at a documented boundary, and reject the rest; a repo that selects `BLE` will have `# noqa: BLE001` markers to read.
- **`gather(return_exceptions=True)` vs `TaskGroup`.** The asyncio docs do not deprecate `gather`; the Python docs' `create_task` note recommends `TaskGroup` for the dangling-reference problem. `gather` remains right when partial results are wanted and every result is inspected. Flag only when exceptions are not handled.
- **Relative imports.** Google forbids them; PEP 8 allows explicit relative imports; many packages use them consistently. `TID252` is opt-in. Follow the repository.
- **`os.path` vs `pathlib`.** `PTH` rules rewrite everything to `pathlib`; Google's parting words say match surrounding code. Treat as a nit unless the diff mixes both in one function.
- **Pydantic for domain objects.** attrs' "Why" argues validation at every boundary is a cost; pydantic-centred codebases (FastAPI) use models everywhere by design. The reviewable point is only a pydantic model on a hot internal path with no untrusted input and a measurable cost.
- **`@staticmethod`.** Google says avoid; it is common and harmless for namespacing. Nit unless the method should obviously be a module function reused elsewhere.
- **Upper bounds on dependencies.** The packaging guide warns against capping `requires-python`; capping library dependencies (`<3`) is widely practised and widely criticised. Ask for the reason; do not block.
- **`from __future__ import annotations` on 3.14.** It is not deprecated per the 3.14 What's New section that was read (the deprecations section of that page was not reached). Treat as a choice to be consistent about, not a defect.
- **Free-threading.** Officially supported in 3.14 but opt-in (`python3.14t`); most projects do not run it. Thread-safety findings in section 3.6 are correctness findings regardless; the free-threaded build only makes the race easier to hit. The HOWTO's detailed per-operation atomicity table (`builtins/threadsafety.html`) was not fetched.
- **tarfile filter on 3.12/3.13.** The 3.12 What's New says unfiltered extraction warns from 3.12; the current tarfile page describes the 3.12–3.13 effective default as `fully_trusted` and recommends passing `filter="data"` explicitly for code that must run below 3.14. Both agree on the fix.
- **ruff preview rules.** Several useful checks (B909, B903, RUF029, RUF056, RUF069, PLW1514, PLC2701, FURB1xx) are preview-only; a repository without `preview = true` does not get them, so those items are live for the reviewer even when the group is selected.
- **mypy vs pyright exhaustiveness.** pyright strict reports non-exhaustive `match` by default; mypy needs `enable_error_code = ["exhaustive-match"]`. A repo on mypy alone should still be asked for `assert_never` arms.
- **The missing OWASP Python sheet.** No OWASP Python-specific cheat sheet exists; the security section is sourced from the stdlib security pages, bandit's catalogue and the generic OWASP sheets. If a stronger single source is wanted, Semgrep's `python` ruleset (found by search, not fetched) is the usual alternative.
