## 2. Detecting the language, edition and toolchain

**Files.** `*.rs` sources; `Cargo.toml` manifests; `Cargo.lock`; `build.rs`; `*.proto`/`*.c` beside a build
script hint at codegen or FFI.

**Edition.** `[package] edition = "2021"` or `"2024"` (absent means 2015). The edition decides several
rules below: `unsafe extern`, `#[unsafe(no_mangle)]`, `static_mut_refs` as a hard error, `unsafe_op_in_unsafe_fn`
warnings, RPIT capture and temporary-scope changes all apply only to 2024 crates. A workspace may mix
editions per member; read each member's `Cargo.toml`. In a workspace, `edition.workspace = true` defers to
`[workspace.package]`.

**MSRV.** `[package] rust-version = "1.xx"` (or inherited). Anything in the diff that needs a newer
compiler (`let else` 1.65, `OnceLock` 1.70, async fn in traits 1.75, `LazyLock` 1.80, `use<..>` 1.82,
edition 2024 1.85) is a defect when it exceeds it. Resolver 3 (default in 2024) makes resolution
MSRV-aware. Clippy reads `rust-version` as its `msrv` unless `clippy.toml` overrides it.

**Toolchain.** `rust-toolchain.toml` (`[toolchain] channel`, `components`, `targets`, `profile`) or the
legacy one-line `rust-toolchain`. A `nightly` channel means `#![feature]` is allowed and Miri may be in CI;
a dated nightly pin means the diff must not need newer nightly features. `targets` listing `wasm32-*`
switches on the WebAssembly group below.

**Workspace vs single crate.** A root `[workspace]` with `members`; a virtual workspace has no
`[package]` and must set `resolver` explicitly. One `Cargo.lock` at the root. Members may inherit
`version`, `edition`, `rust-version`, `license`, dependencies (`{ workspace = true }`) and `[lints]
workspace = true`; a diff that adds a plain dependency version to a member when the workspace already
pins it is a divergence.

**Library vs binary.** `src/lib.rs` (or `[lib]`) is a library; `src/main.rs` and `src/bin/*.rs` (or
`[[bin]]`) are binaries; `crate-type = ["cdylib"]` means an FFI or wasm artifact, `"proc-macro"` a proc
macro. The distinction changes the error-handling rules: libraries return `Result` with a typed error and
must not `unwrap`/`panic` on inputs; binaries may use `anyhow`/`eyre`, `main() -> Result<(), E>` and
`expect` at the edges. `publish = false` means semver and metadata rules are relaxed; a crate with
`version` and no `publish = false` is going to crates.io, so C-METADATA, C-STABLE, `Cargo.lock`
and `cargo semver-checks` apply.

**WebAssembly.** `wasm32-unknown-unknown`, `wasm32-wasip1` (or `wasm32v1-none` for `no_std`) in
`rust-toolchain.toml targets`, `.cargo/config.toml [build] target`, `[target.wasm32-unknown-unknown.*]`
tables, `wasm-bindgen`/`js-sys`/`web-sys` dependencies, `#[wasm_bindgen]` attributes,
`#[cfg(target_arch = "wasm32")]` or `#[cfg(all(target_family = "wasm", target_os = "unknown"))]`.

**Tooling config to glance at before flagging anything.**
- `[lints.rust]` / `[lints.clippy]` / `[lints.rustdoc]` in `Cargo.toml` (or `[workspace.lints]`): which groups are `warn`/`deny`, and whether `priority = -1` is on the group so individual overrides win (`clippy::lint_groups_priority` catches the mistake). `unsafe_code = "forbid"` means no `unsafe` review is needed unless the diff removes it.
- `clippy.toml`: `msrv`, `allow-unwrap-in-tests`, `allow-expect-in-tests`, `allow-panic-in-tests`, `allow-print-in-tests`, `allow-dbg-in-tests`, `disallowed-methods`/`-types`/`-macros` (the project's own bans), `too-many-arguments-threshold`, `enum-variant-size-threshold`, `large-error-threshold`, `avoid-breaking-exported-api`, `check-private-items`, `allowed-wildcard-imports`, `allowed-duplicate-crates`.
- `rustfmt.toml` / `.rustfmt.toml`: if present and CI runs `cargo fmt --check`, do not comment on layout at all. `style_edition = "2024"` changes import sorting.
- `deny.toml`: licences allow-list, `[bans]` (duplicate versions, banned crates), `[advisories]`, `[sources]` (which registries and git hosts are allowed).
- `supply-chain/` (cargo vet), `.cargo/audit.toml`, `Cargo.lock` presence, `.github/workflows/*.yml` or `Justfile`/`Makefile` for `cargo clippy -- -D warnings`, `cargo miri test`, `cargo nextest`, `cargo semver-checks`, `cargo hack --rust-version`.
- Crate-root attributes in `lib.rs`/`main.rs`: `#![forbid(unsafe_code)]`, `#![warn(missing_docs)]`, `#![deny(unsafe_op_in_unsafe_fn)]`, `#![no_std]`, `#![warn(clippy::pedantic)]`, and the anti-pattern `#![deny(warnings)]`.

## 3. Checklist

Format: **Rule.** Signal in the diff. Why. [source; lint or C-id]

### 3.1 Ownership, borrowing and types

- **Borrow in parameters; own only when the function keeps the value.** Signal: `fn f(s: String)` / `fn f(v: Vec<T>)` whose body only reads; or `fn f(x: &T)` followed by `x.clone()` to store it. Why: the caller decides where to copy; borrow-then-clone forces an allocation the caller could have avoided. [C-CALLER-CONTROL; `clippy::needless_pass_by_value` (pedantic)]
- **`&str` and `&[T]` over `&String`, `&Vec<T>`, `&PathBuf`, `&Box<T>`.** Signal: those reference types in a signature. Why: a slice accepts every owner through deref coercion with no loss; `&Box<T>` forces callers to box. [Book ch04-03; `clippy::ptr_arg` (style), `clippy::borrowed_box` (complexity)]
- **A `clone()` that the borrow checker did not ask for.** Signal: `.clone()`, `.to_owned()`, `.to_string()`, `.to_vec()` on a value that is then dropped or whose original is never used again; `.cloned()` before `take`/`skip`/`last`; `.clone()` on a `Copy` type. Why: pointless allocations; `Copy` types clone for generic code only. [`clippy::redundant_clone` (nursery), `clippy::unnecessary_to_owned` (perf), `clippy::iter_overeager_cloned` (perf), `clippy::clone_on_copy` (complexity)]
- **`Rc::clone(&x)` / `Arc::clone(&x)` spelling for pointer clones.** Signal: `x.clone()` where `x: Arc<_>`. Why: makes clear only the pointer is cloned, not the payload. [`clippy::clone_on_ref_ptr` (restriction)]
- **`Rc<RefCell<T>>` and `Arc<Mutex<T>>` as a reflex.** Signal: new fields of these types, especially `Rc<Mutex<_>>` or `Arc<RefCell<_>>` (wrong pairing); `Arc<Vec<_>>`/`Rc<String>` (`Rc<[T]>`/`Rc<str>` are smaller and cannot be mutated by surprise); `Rc<Rc<_>>`, `Arc<Box<_>>`, `Box<Vec<_>>`, `Vec<Box<Sized>>`. Why: `Rc` is single-threaded, `Mutex` multithreaded; redundant indirection; cycles leak. [`clippy::rc_mutex` (restriction), `clippy::rc_buffer` (restriction), `clippy::redundant_allocation` (perf), `clippy::box_collection` (perf), `clippy::vec_box` (complexity); std::rc docs]
- **Cycles through `Rc`/`Arc` need `Weak` on the back edge.** Signal: parent↔child or observer structures where both directions are strong. Why: a cycle's counts never reach zero; the leak is memory-safe so nothing warns. [Book ch15-06; std::rc]
- **Lifetimes in struct fields and `'static` bounds need a reason.** Signal: `struct Foo<'a> { s: &'a str }` where an owned `String`/`Cow<'a, str>` would do; `T: 'static` added only to make a spawn compile. Why: a borrowing struct infects every user with a lifetime; `'static` forbids borrowed data forever. Prefer `Cow<'a, B>` when the data is sometimes owned. [std::borrow::Cow; `clippy::owned_cow` (style), `clippy::needless_lifetimes` / `extra_unused_lifetimes` (complexity)]
- **Newtypes for distinct meanings; enums instead of `bool`/`Option` arguments.** Signal: `fn new(small: bool, round: bool)`, two `f64` parameters with different units, `fn f(x: Option<u32>)` where `None` is a mode. Why: `Widget::new(Small, Round)` cannot be transposed; a newtype costs nothing. [C-NEWTYPE, C-CUSTOM-TYPE; `clippy::fn_params_excessive_bools`, `clippy::struct_excessive_bools` (pedantic)]
- **Conversions use `From`/`TryFrom`/`AsRef`, never a hand-rolled `Into` or an `as`.** Signal: `impl Into<T> for U`; `fn to_foo(&self)` where `From` fits; `x as u8` from a wider integer. Why: `Into`/`TryInto` come free from `From`/`TryFrom`; `as` silently truncates (`1234u16 as u8 == 210`), wraps signs and saturates floats. Use `u8::try_from(x)` or `u32::from(x)`. [C-CONV-TRAITS; Reference operator-expr; `clippy::cast_possible_truncation`, `cast_sign_loss`, `cast_possible_wrap`, `cast_lossless` (pedantic), `clippy::as_conversions` (restriction), `clippy::as_underscore` (restriction)]
- **`Deref` only on smart pointers.** Signal: `impl Deref for Wrapper { type Target = Inner }` to get "inheritance" or to save typing accessors. Why: method resolution rules are designed for pointers; traits on `Inner` are not inherited; readers are surprised. [C-DEREF; patterns/anti_patterns/deref]
- **`#[derive]` completeness and `Copy` on large types.** Signal: a new public type without `Debug`; a plain data type missing `Clone`, `PartialEq`, `Eq`, `Hash`, `Default` where they are meaningful; `#[derive(Copy)]` on a type with arrays or many fields (copies hide `memcpy`s); `PartialEq` derived without `Eq` when `Eq` holds; a `new()` with no `Default`. Why: the orphan rule means only this crate can add them. [C-COMMON-TRAITS, C-DEBUG; `missing_debug_implementations` (rustc, allow), `clippy::derive_partial_eq_without_eq` (nursery), `clippy::new_without_default` (style), `clippy::large_types_passed_by_value` (pedantic)]
- **`Ord`/`PartialOrd`/`PartialEq`/`Eq`/`Hash` must agree.** Signal: `#[derive(PartialOrd)]` with a manual `Ord` (or vice versa); `#[derive(Hash)]` with a manual `PartialEq` that ignores a field; `partial_cmp` not written as `Some(self.cmp(other))`; `f64`/`f32` fields in a type deriving `Ord`; a `HashMap` key with `Cell`/`RefCell`/`Mutex` inside. Why: `partial_cmp(a,b) == Some(cmp(a,b))` and `k1 == k2 -> hash(k1) == hash(k2)` are required; `BTreeMap`/`HashMap` break silently otherwise. Derive all four or hand-write all four. [std::cmp::Ord, std::hash::Hash; `clippy::derive_ord_xor_partial_ord`, `clippy::derived_hash_with_manual_eq` (correctness), `clippy::mutable_key_type` (suspicious)]
- **Exhaustive `match` over `_` on your own enums.** Signal: `_ =>` arm in a match on an enum from this crate or a dependency where only one variant remains uncovered; `use Enum::*` globs. Why: a new variant is silently swallowed; prefixed variants read clearer. Conversely a wildcard is required for `#[non_exhaustive]` foreign enums. [`clippy::match_wildcard_for_single_variants` (pedantic), `clippy::wildcard_enum_match_arm` (restriction), `clippy::enum_glob_use` (pedantic); Reference type_system]
- **Modern control flow: `let else`, `matches!`, `if let` for one arm.** Signal: `let x = match opt { Some(x) => x, None => return Err(..) };` (write `let Some(x) = opt else { return Err(..) };`, MSRV ≥ 1.65); `match` returning only `true`/`false`; `match` with one arm plus `_ => {}`; `mem::replace(&mut o, None)` (use `take()`), `mem::replace(&mut x, Default::default())` (use `mem::take`). [`clippy::manual_let_else` (pedantic), `clippy::match_like_matches_macro`, `single_match`, `mem_replace_option_with_none`, `mem_replace_with_default` (style); std::mem::take]
- **Integer overflow is a decision, not an accident.** Signal: `a + b`, `a * b`, `x << n`, `a - b` on untrusted or unbounded values; `len() - 1`; `as usize` of a negative; relying on wrap in release. Why: debug panics, release wraps two's complement ("relying on wrapping is considered an error"); `/`, `%` by zero and `MIN / -1` panic in every mode; shifts ≥ bit width panic in debug. Use `checked_`, `saturating_`, `wrapping_`, `overflowing_`, or prove the bound in a comment. [Book ch03-02; Reference overflow; `clippy::arithmetic_side_effects` (restriction), `clippy::integer_division` (restriction)]
- **Indexing that can panic.** Signal: `v[i]`, `&s[a..b]`, `map["k"]` on data the function did not bound-check; string byte slicing `&s[0..1]`. Why: out-of-range indexing panics; a string slice off a char boundary panics; prefer `.get(i)`, `.get(a..b)`, `s.is_char_boundary`. In a library, an index panic on caller data is a bug unless documented under `# Panics`. [`clippy::indexing_slicing` (restriction), `clippy::string_slice` (restriction), `clippy::out_of_bounds_indexing` (correctness)]
- **Strings: `chars()` is scalar values, not graphemes; `len()` is bytes.** Signal: `.chars().count()` used for display width; `.chars().rev()` to "reverse a string"; `.len()` compared with a character count; `.chars().nth(i)` in a loop (O(n²)). Why: a user-perceived character may be several `char`s; grapheme segmentation needs a crate (`unicode-segmentation`). [Book ch08-02]
- **Floats: no `==`, no `Ord`, order with `total_cmp`.** Signal: `a == b` on `f32`/`f64`; `(a - b) < EPSILON` without `.abs()`; `partial_cmp(..).unwrap()` in a sort (panics on NaN); `x as i32` of a possibly-NaN float (becomes 0). Why: NaN breaks `Eq`/`Ord`; `f64::total_cmp` gives a total order (`-NaN < -inf < ... < +inf < +NaN`). [`clippy::float_cmp` (pedantic), `clippy::float_equality_without_abs` (suspicious), `clippy::cast_nan_to_int` (suspicious); std::cmp::Ord, Reference float-to-int]
- **Shadowing that changes meaning.** Signal: `let x = ...;` rebinding a name to an unrelated value in the same scope. Why: the reader must track which `x` is live. (Rebinding after a conversion, `let x = x.parse()?`, is idiomatic.) [`clippy::shadow_unrelated` (restriction)]
- **`Option<Option<T>>`, `Result<_, ()>`, `LinkedList`, `Option<Box<T>>` and other type smells.** Signal: those types in signatures. Why: nested `Option` hides which `None` means what (write an enum); `()` is not an error (C-GOOD-ERR); `LinkedList` is slower than `Vec`/`VecDeque`; `Option<Box<T>>` is fine (the niche makes it pointer-sized) but `Option<Option<..>>` is not. [`clippy::option_option` (pedantic), `clippy::result_unit_err` (style), `clippy::linkedlist` (pedantic); std::option Representation]

### 3.2 Error handling and panics

- **Libraries return `Result`; panics are for broken invariants only.** Signal: `unwrap()`, `expect()`, `panic!`, `unreachable!`, `assert!` on inputs, I/O, parsing, environment, or anything the caller controls, in a crate with `src/lib.rs`. Why: panicking "makes the decision that a situation is unrecoverable on behalf of the calling code"; a contract violation (caller bug) may panic and must be documented under `# Panics`. [Book ch09-03; `clippy::unwrap_used`, `expect_used`, `panic`, `unreachable` (restriction); C-FAILURE]
- **`unwrap`/`expect` inside a function that already returns `Result`/`Option`.** Signal: `?`-able expression unwrapped in a `-> Result<_, _>` body. Why: promotes a recoverable error to a crash where `?` was one character away. [`clippy::unwrap_in_result`, `clippy::panic_in_result_fn` (restriction)]
- **An `expect` message states the invariant, not the failure.** Signal: `.expect("failed to parse")`, `.expect("unwrap")`, or `.expect(&format!(..))` (the format runs on the success path too). Why: the message is the reviewer's hook for "why can this not fail"; the Book's model is `.expect("Hardcoded IP address should be valid")`. Use `unwrap_or_else(|| panic!(..))` when the message is expensive. [Book ch09-03; `clippy::expect_fun_call` (perf)]
- **`?` with `From` conversions; typed errors in libraries.** Signal: `.map_err(|e| MyError::Io(e))?` repeated where `impl From<io::Error> for MyError` (or `#[from]`) would do; `.map_err(|_| MyError::Other)` discarding the cause. Why: `?` calls `From::from`; dropping the source loses the chain. [RBE wrap_error; `clippy::map_err_ignore` (restriction)]
- **`thiserror` (or hand-written `Error`) for libraries, `anyhow`/`eyre` for binaries.** Signal: `anyhow::Result` in a public function of a library crate; `Box<dyn Error>` in a public API; a library error enum without `impl std::error::Error`, without `Display`, or with `description()`. Why: a public error type must be `Error + Send + Sync + 'static` so callers can match, `?` into their own type and `downcast_ref`; `anyhow` is for applications. `Box<dyn Error + Send + Sync>` is acceptable for an application boundary or a prototype. [C-GOOD-ERR; thiserror and anyhow docs; RBE boxing_errors]
- **Error enum design: `#[non_exhaustive]`, `source()`, `Display` in lowercase without trailing punctuation.** Signal: a new public error enum without `#[non_exhaustive]`; a wrapping variant whose `source()` returns `None` (`#[source]`/`#[from]` missing); `Display` text that repeats the inner error's text (double printing in chains, use `#[error(transparent)]` or describe only this layer). [C-GOOD-ERR; Cargo semver (adding a variant is major without `non_exhaustive`); thiserror docs]
- **Large error types bloat every `Result`.** Signal: `Result<T, BigEnum>` where the enum carries `String`s, `PathBuf`s and nested errors (> 128 bytes by default). Why: the `Result` is as large as its error on every call; box the error or the large variant. [`clippy::result_large_err` (perf), `clippy::large_enum_variant` (perf)]
- **Discarding `Result`s.** Signal: `let _ = fallible();`, `fallible().ok();`, `_ = f();` on a `Result` that matters (write, flush, send, remove, lock); a `#[must_use]` value dropped. Why: `unused_must_use` warns on a bare statement, but `let _ =` silences it, so each one needs a comment saying why the error is irrelevant. [`unused_must_use` (rustc, warn), `unused_results` (rustc, allow); `clippy::let_underscore_must_use`, `let_underscore_untyped` (restriction), `clippy::unused_result_ok`]
- **Partial I/O.** Signal: `.read(&mut buf)` or `.write(&bytes)` whose returned count is ignored (`let _ = w.write(..)?`, `w.write(..)?;`). Why: both may process part of the buffer; use `write_all`/`read_exact` or loop on the count. [`clippy::unused_io_amount` (correctness)]
- **`#[must_use]` on builders, constructors and pure functions.** Signal: a public `fn` returning a new value whose result is meaningless to drop (`fn with_x(self, ..) -> Self`, `fn checked_add`) without `#[must_use]`; `#[must_use]` on a `-> ()` function or on a function returning an already-`#[must_use]` type. [Reference diagnostics; `clippy::must_use_candidate` (pedantic), `clippy::return_self_not_must_use` (pedantic), `clippy::must_use_unit`, `double_must_use` (style)]
- **Destructors never fail, panic or block.** Signal: `impl Drop` containing `unwrap`, `expect`, `panic!`, `assert!`, `.lock().unwrap()`, blocking I/O, `block_on`. Why: a panic during unwinding is a double panic and aborts; give the fallible teardown a `close(self) -> Result` and have `drop` log and continue. [C-DTOR-FAIL, C-DTOR-BLOCK; std::ops::Drop]
- **`std::process::exit` only at the top of `main`.** Signal: `process::exit(..)` inside library code, handlers or after resources are open. Why: no destructors run on any thread (buffers not flushed, temp files kept, locks not released); return `ExitCode` or `Result` from `main`. [std::process::exit; `clippy::exit` (restriction)]
- **Debug leftovers.** Signal: `dbg!`, `println!`/`eprintln!` in library code (binaries' intended output is fine), `todo!()`, `unimplemented!()` in a path that ships, `{:?}` in user-facing text. [`clippy::dbg_macro`, `print_stdout`, `print_stderr`, `use_debug`, `todo`, `unimplemented` (restriction)]
- **`unwrap_or_default`, `unwrap_or_else`, `ok_or_else` instead of eager constructs.** Signal: `.unwrap_or(Vec::new())`, `.unwrap_or(expensive())`, `.ok().expect(..)`, `.map(f).unwrap_or(d)`, `match { Some(x) => x, None => Default::default() }`. [`clippy::unwrap_or_default` (style), `or_fun_call` (nursery), `ok_expect` (style), `map_unwrap_or` (pedantic), `manual_unwrap_or_default` (suspicious)]

### 3.3 Unsafe

- **Every `unsafe` block and `unsafe impl` has a `// SAFETY:` comment directly above it.** Signal: `unsafe {` or `unsafe impl` with no comment, or a comment that restates the operation ("call foo") rather than the invariant that makes it sound ("`mid` was just checked to be a char boundary"). Why: the comment is where soundness is argued and reviewed; writing it finds bugs. Reject `// SAFETY: trust me`. [std-dev-guide safety-comments; `clippy::undocumented_unsafe_blocks` (restriction), `clippy::unnecessary_safety_comment`]
- **Every `unsafe fn` and `unsafe trait` documents its contract in `# Safety`; safe functions do not.** Signal: a new `pub unsafe fn` without a `# Safety` doc section; a safe `pub fn` with one (then either the fn should be `unsafe` or the section is wrong). Why: the caller takes on the obligation and must be told what it is. [std-dev-guide; Reference unsafe-keyword; C-FAILURE; `clippy::missing_safety_doc` (style), `clippy::unnecessary_safety_doc` (restriction)]
- **Soundness: no safe public function may cause UB for any argument.** Signal: a safe `pub fn` that dereferences a raw-pointer parameter, calls `get_unchecked(i)` with a caller-supplied `i`, trusts a caller-supplied length, or returns `&mut` derived from `&`. Why: soundness is "impossible for safe code to cause UB using its public API"; the function must either check, or be `unsafe fn` with the precondition documented. [UCG glossary; `clippy::not_unsafe_ptr_arg_deref` (correctness), `clippy::mut_from_ref` (correctness)]
- **Validity invariants are instantaneous UB; check the list.** Signal: `transmute` or raw `read` producing a `bool` not 0/1, an `enum` with a bad discriminant, a `char` surrogate, a null `fn` pointer, a dangling/unaligned/null `&T`/`Box`, a `NonZero`/`NonNull` holding zero, a `str` with uninitialised bytes, or any read of uninitialised integers/floats/pointers. Why: producing the invalid value is UB even if never used. [Reference behavior-considered-undefined; Nomicon what-unsafe-does; `invalid_value` (rustc, warn)]
- **Aliasing: `&mut T` is unique, `&T` is immutable, `Box` counts as `&'static mut`.** Signal: two live `&mut` to one place; `&T` to memory written through a raw pointer without `UnsafeCell`; `transmute::<&T, &mut T>` (always UB); `as_ptr()` from `&self` cast to `*mut` and written. Why: the optimiser assumes the rules; violation is UB even inside private fields. [Reference aliasing rules; Nomicon transmutes; `clippy::as_ptr_cast_mut` (nursery), `clippy::transmute_ptr_to_ref` (complexity)]
- **`static mut`: no references, ever; 2024 makes it an error.** Signal: `static mut X`, `&X`, `&mut X`, `X.len()`, `println!("{X:?}")`. Why: creating the reference is UB if any other reference exists; `static_mut_refs` is warn in 2021 and deny in 2024. Replace with `AtomicT`, `Mutex<T>` in a plain `static`, `OnceLock`/`LazyLock`, or `&raw mut X` for FFI. [Edition guide static-mut-references; `static_mut_refs` (rustc)]
- **`unsafe impl Send`/`Sync` carries a written argument about every field.** Signal: `unsafe impl<T> Send for Foo<T> {}` without `where T: Send`; an impl on a type containing `Rc`, `RefCell`, `*mut T`, `MutexGuard` or an unbounded `T`; `Arc<T>` built around a `!Send + !Sync` payload. Why: the auto trait was declined for a reason; sending sends every field; data races are UB. The Nomicon's model is "`Send` where `T: Send`" plus a paragraph on why the pointer is uniquely owned. [Nomicon send-and-sync; C-SEND-SYNC (add compile-time assertions); `clippy::non_send_fields_in_send_ty` (nursery), `clippy::arc_with_non_send_sync`]
- **`transmute` is the last resort and must be fully typed.** Signal: `mem::transmute` without `::<Src, Dst>`; transmute between `repr(Rust)` types (layout unspecified, even `Vec<i32>` vs `Vec<u32>`); between collections; integer-to-pointer; `transmute_copy`; where `from_ne_bytes`, `as`, `ptr::cast`, `NonZero::new` or `bytemuck` would do. Why: size mismatch, invalid values and layout differences are UB; inference may pick an unintended type. [Nomicon transmutes; `unnecessary_transmutes` (rustc, warn); `clippy::missing_transmute_annotations` (suspicious), `transmute_undefined_repr` (nursery), `unsound_collection_transmute`, `wrong_transmute`, `transmuting_null`, `transmute_null_to_fn`, `eager_transmute` (correctness), `transmute_ptr_to_ptr` (pedantic)]
- **Uninitialised memory: `MaybeUninit`, `ptr::write`, never `set_len` first.** Signal: `mem::uninitialized()`, `mem::zeroed()` for a type with a niche or references, `MaybeUninit::uninit().assume_init()`, `Vec::with_capacity(n)` then `set_len(n)` before writing, `&mut *uninit.as_mut_ptr()` field access (use `&raw mut (*p).field`), `=` assignment into uninit memory (drops garbage; use `ptr::write`). [Nomicon unchecked-uninit; `clippy::uninit_vec`, `uninit_assumed_init`, `mem_replace_with_uninit` (correctness)]
- **Unsafe code must not rely on `Drop` running, on poisoning, or on `Eq`/`Ord`/`Hash` being correct.** Signal: a guard type whose soundness depends on its destructor (`mem::forget` defeats it); a collection using a user `Ord` to index raw memory; relying on `Mutex` poisoning for memory safety. Why: leaks are safe (`thread::scoped` was removed for this); logic errors in trait impls are permitted and must not become UB. Design so the leaked state is safe ("leak amplification", as `Vec::drain` sets `len = 0`). [Nomicon leaking; std::sync::Mutex; std::cmp::Ord; `clippy::mem_forget` (restriction)]
- **FFI: `unsafe extern` (2024), exact signatures, `repr(C)`, no unwinding into C.** Signal: `extern "C" { .. }` without `unsafe` in a 2024 crate; `safe fn` qualifier on an import that has preconditions; a Rust struct passed to C without `#[repr(C)]`; an `extern "C" fn` callback whose body can panic without `catch_unwind` (abort at best, UB if the ABI is `C-unwind` mismatched); `Box<T>`/`&T` in a signature where C may pass null (use `Option<&T>`/`*const T`); an opaque type modelled as an empty enum (use a struct with `PhantomData<(*mut u8, PhantomPinned)>`); `#[link]` kind wrong; `CString` not used for C strings; `set_len` after an out-parameter without checking the reported length ≤ capacity. [Nomicon ffi; Edition guide unsafe-extern; `improper_ctypes` (rustc, warn); `missing_unsafe_on_extern`]
- **`#[no_mangle]`, `#[export_name]`, `#[link_section]` are `#[unsafe(..)]` in 2024 and need a SAFETY comment.** Signal: those attributes; an exported symbol named like a libc function (`malloc`, `loop`). Why: the symbol namespace is global; a collision crashes safe code. [Edition guide unsafe-attributes; `unsafe_attr_outside_unsafe`; `unsafe_code` (rustc) also covers them]
- **`unsafe_op_in_unsafe_fn`: one small `unsafe {}` per operation inside an `unsafe fn`.** Signal: an `unsafe fn` body using unsafe operations bare (2021), or one giant `unsafe {}` around a whole function. Why: 2024 warns by default; each operation gets its own justification; smaller blocks keep `unused_unsafe` meaningful. [Edition guide unsafe-op-in-unsafe-fn; `clippy::multiple_unsafe_ops_per_block` (restriction)]
- **`Pin` and structural pinning.** Signal: `Pin::new_unchecked`, `get_unchecked_mut`, `map_unchecked_mut`, a manual `impl Unpin`, `Drop` on a pinned type that moves fields, `#[repr(packed)]` on a pinned type, a method that moves out of a structurally pinned field. Why: the pinned value's memory must not be invalidated until `drop` has run; overwriting without `drop` is UB; structural pinning imposes four obligations (Unpin only if fields are, pinned destruction, drop guarantee, no moving out). Prefer `pin!`, `Box::pin` and the `pin-project` crate. [std::pin]
- **Unsafe for speed needs a benchmark in the PR.** Signal: `get_unchecked`, `unchecked_add`, `from_utf8_unchecked`, `unwrap_unchecked`, `assume_init` introduced "for performance" with no numbers, no `_unchecked`-suffixed safe sibling, and no proof of the bound. Why: C-VALIDATE puts checked first and unchecked as the documented opt-out; the checked version usually optimises to the same code. [C-VALIDATE; Nomicon what-unsafe-does]
- **Miri-clean where the crate has it.** Signal: new unsafe code without a test that exercises it (Miri only checks executed paths); `#[cfg(miri)]` used to skip the very test that matters. Why: Miri finds OOB, UAF, uninit, misalignment, invalid values, data races and aliasing violations, but only on paths the tests run and never through FFI. [Miri README]

### 3.4 Traits, generics and API design

- **Naming: RFC 430 casing, `as_`/`to_`/`into_`, no `get_`, `iter`/`iter_mut`/`into_iter`.** Signal: `get_name()` (write `name()`), `to_bytes(&self) -> &[u8]` (free borrow is `as_bytes`), `into_x(&self)`, `as_x(self)`, acronyms in caps (`HTTPClient`), `-rs` crate suffixes, iterator types not named after their method (`Iter`, `IntoIter`, `Keys`). [C-CASE, C-CONV, C-GETTER, C-ITER, C-ITER-TY; `clippy::wrong_self_convention` (style), `clippy::should_implement_trait` (style), `clippy::module_name_repetitions` (restriction), `clippy::enum_variant_names` (style)]
- **Constructors: `new`, `with_*`, `from_*`; `new()` agrees with `Default`.** Signal: a no-argument `new()` that differs from `default()`; a free function that should be a method; `fn parse(input, out: &mut Vec<_>)` out-parameters. [C-CTOR, C-METHOD, C-NO-OUT]
- **Generics vs `impl Trait` vs `dyn Trait`: pick for the reason, not habit.** Signal: `Box<dyn Trait>` in a hot path or field where one concrete type ever appears; a generic `<T: Trait>` where heterogeneous storage or binary size matters (`dyn` is right there); `impl Trait` in argument position of a public API (callers cannot turbofish); a return-position `impl Iterator` that callers need to name or require `Clone`/`Debug` on (use a newtype). Why: generics give inlining and inference, `dyn` gives one copy and heterogeneity; neither is free. [C-GENERIC, C-OBJECT, C-NEWTYPE-HIDE; `clippy::impl_trait_in_params` (restriction)]
- **Accept the most general input.** Signal: `fn f(v: &Vec<i64>)`/`fn f(v: Vec<i64>)` that only iterates (take `impl IntoIterator<Item = i64>` or `&[i64]`); `R: Read`/`W: Write` taken by `&mut` in a generic function (take by value; `&mut R` also implements `Read`); `&Option<T>` parameters (take `Option<&T>`). [C-GENERIC, C-RW-VALUE; `clippy::ref_option` (pedantic)]
- **Dyn-compatibility (object safety) is decided early.** Signal: a trait meant to be boxed gaining a generic method, a `-> Self`, or `async fn`/`-> impl Trait` without `where Self: Sized`. Why: `dyn Trait` stops compiling; async fn in traits is not dyn-compatible (use `async-trait` or a boxed-future method). [C-OBJECT; blog async-fn-rpit-in-traits]
- **Sealed traits for traits downstream must not implement.** Signal: a public trait with methods you expect to add later, no `private::Sealed` supertrait, no "this trait is sealed" doc line. Why: adding a required method to an open trait is a major change. [C-SEALED; Cargo semver traits]
- **Private fields, `#[non_exhaustive]`, no derivable bounds on structs.** Signal: a new public struct with all-`pub` fields (adding any field later is major; `#[non_exhaustive]` makes it minor); a public enum that will grow without `#[non_exhaustive]`; `struct Foo<T: Clone + Debug>` where the bound is used only by impls (put it on the impl). [C-STRUCT-PRIVATE, C-STRUCT-BOUNDS; Reference type_system; Cargo semver; `clippy::exhaustive_enums`, `exhaustive_structs` (restriction)]
- **Builders for many optional inputs; non-consuming by default.** Signal: a constructor with > 4 parameters or several `bool`s/`Option`s; a `fn new(a, b, c, d, e, f, g)`. Why: readability and future options; `&mut self` builders allow stepwise configuration. [C-BUILDER; `clippy::too_many_arguments` (complexity, threshold 7)]
- **Validate arguments; `debug_assert!` for expensive checks; `_unchecked` siblings for opt-out.** Signal: a public fn that assumes a sorted slice, a non-empty buffer, or UTF-8 and does nothing when the assumption fails. [C-VALIDATE]
- **Implement the common traits eagerly; `Serialize`/`Deserialize` behind a `serde` feature.** Signal: a new public data type with no `Debug`/`Clone`/`PartialEq`; serde derives unconditional in a library (forces the dependency); a `Debug` that prints nothing or omits fields silently. [C-COMMON-TRAITS, C-SERDE, C-DEBUG-NONEMPTY; `clippy::missing_fields_in_debug` (pedantic)]
- **Operator overloads and `Deref` only where the operation really is that operation.** Signal: `impl Mul` for concatenation, `impl Add` for `String`-like append (also the `x + y` asymmetry), `impl Deref` to reach a field. [C-OVERLOAD, C-DEREF; `clippy::string_add` (restriction)]
- **`#[inline]` only with evidence; `#[inline(always)]` almost never.** Signal: `#[inline(always)]` on non-trivial bodies; blanket `#[inline]` on every public fn (acceptable only in small, generic-heavy crates). Why: cross-crate inlining needs `#[inline]` or LTO, but `always` is often misused and should be measured. [`clippy::inline_always` (pedantic), `clippy::missing_inline_in_public_items` (restriction)]
- **`const fn` is a public commitment; `pub` that is not reachable should be `pub(crate)`.** Signal: `pub fn` in a private module that is never re-exported (`unreachable_pub`); removing `const` from a public fn (breaking). [`unreachable_pub` (rustc, allow); `clippy::missing_const_for_fn` (nursery)]
- **Wire-stable names and semver on every public change.** Signal: renaming or removing a public item, changing a signature, tightening a bound, adding a variant to an exhaustive enum, adding a field to a public-fields struct, raising MSRV, removing a feature, switching from `no_std` to `std`. Why: each is major per Cargo's semver catalogue; `cargo semver-checks` catches many but not type changes in fields/params or feature subsets. [Cargo semver; cargo-semver-checks README]

### 3.5 Concurrency and async

- **Never hold a `std::sync::MutexGuard`, `RwLock` guard, `RefCell` `Ref`/`RefMut` across `.await`.** Signal: `let g = m.lock().unwrap(); ... .await` in one scope; `if let Some(x) = *lock.read().unwrap() { .. } else { lock.write() }` (2021: the read guard is still held in `else`, deadlock); a guard in a `match` scrutinee whose arm locks again. Why: the task may be suspended while holding the lock and resumed on another thread; `RefCell` panics on overlap. Scope the guard in a block or move the lock into a non-async helper. [Tokio shared-state; Edition guide if-let scope; `clippy::await_holding_lock`, `await_holding_refcell_ref` (suspicious), `clippy::significant_drop_in_scrutinee` (nursery), `clippy::significant_drop_tightening` (nursery)]
- **`std::sync::Mutex` for data, `tokio::sync::Mutex` only for a resource held across awaits.** Signal: `tokio::sync::Mutex<HashMap<_, _>>` around plain data (slower, FIFO, and the usual sign that a guard is held across awaits for no reason); `std::sync::Mutex` around a database connection used across awaits. [Tokio sync::Mutex docs; Tokio shared-state]
- **Mutex poisoning is handled deliberately.** Signal: `.lock().unwrap()` everywhere in a long-lived service (one panic poisons the lock and every later `lock()` panics); `into_inner()` recovery without restoring a consistent value; `RwLock` assumed poisoned by reader panics (only writers poison). Why: poisoning is advisory; either propagate (`unwrap`, documented), recover with `PoisonError::into_inner` + `clear_poison` (1.77), or use `parking_lot` which does not poison. [std::sync::Mutex, std::sync::RwLock; `clippy::mutex_atomic`, `mutex_integer` (restriction) for `Mutex<bool/int>` that should be atomics]
- **Blocking inside async: `std::thread::sleep`, `std::fs`, blocking sockets, `block_on`, heavy CPU.** Signal: those calls in an `async fn` or in a future polled by Tokio; `reqwest::blocking`, `rusqlite` calls, `std::process::Command::output()` inline. Why: the thread stalls every task scheduled on it; the rule of thumb is 10–100 µs between awaits. Move it to `spawn_blocking` (bounded I/O), `rayon` + `oneshot` (CPU), or a dedicated `std::thread` (long-lived loops). `spawn_blocking` tasks cannot be aborted once started. [ryhl.io async-what-is-blocking; Tokio spawn_blocking]
- **Detached tasks and threads.** Signal: `tokio::spawn(..);` with the `JoinHandle` dropped and no supervision, cancellation or error path; `std::thread::spawn(..)` whose handle is dropped. Why: dropping a `JoinHandle` detaches the task; its panic is caught by Tokio and lost unless the handle is awaited (`JoinError::is_panic`); a std thread's panic is only visible through `join()`. Keep the handle in a `JoinSet`, `TaskTracker` or struct, or write the comment that explains fire-and-forget. [Tokio JoinHandle; std::thread::spawn]
- **`select!` and cancellation safety.** Signal: `tokio::select!` in a `loop` whose branch calls a non-cancellation-safe future (`read_exact`, `write_all`, a hand-written `async fn` that holds partial state) and recreates it every iteration; a future with side effects dropped mid-way. Why: losing a branch drops its future, so partially consumed input is lost; pin a single future outside the loop or use cancellation-safe primitives (`mpsc::recv`, `Notify::notified`). [Tokio select tutorial]
- **Futures that must be `Send`.** Signal: `Rc`, `RefCell`, `MutexGuard`, `*mut T`, non-`Send` trait objects (`Box<dyn Error>` without `+ Send + Sync`) alive across an `.await` in a future handed to `tokio::spawn` or a multi-thread runtime; a public `async fn` in a trait (1.75+) that callers will spawn (the trait author fixes the bounds; add `-> impl Future<Output = T> + Send` or use `trait-variant`). [`clippy::future_not_send` (nursery); `async_fn_in_trait` (rustc, warn on public traits); blog async-fn-rpit-in-traits]
- **`async fn` that never awaits; futures that are too big.** Signal: `async fn` with no `.await` (callers pay for a runtime they do not need); huge `async` state machines (`clippy::large_futures` threshold 16 KiB) causing stack overflows, fix with `Box::pin`. [`clippy::unused_async`, `clippy::large_futures` (pedantic)]
- **Bounded channels unless unbounded is argued.** Signal: `mpsc::unbounded_channel()`, `crossbeam::unbounded()` fed by an external source; receivers dropped with messages still queued (call `close()` then drain). Why: a bounded channel is the backpressure; unbounded grows without limit. Match the channel to the receiving side's sync/async nature. [Tokio mpsc]
- **`RwLock` is not fair; readers can starve writers and re-entrant reads can deadlock.** Signal: a reader taking a second read lock while a writer waits; hot-path `RwLock` where a `Mutex` or sharding would do. Why: priority policy is OS-dependent and undocumented. [std::sync::RwLock; Tokio shared-state (sharding)]
- **Atomics: `SeqCst` is fine; `Relaxed` needs a one-line justification; `Release`/`Acquire` must pair.** Signal: `Ordering::Relaxed` on a flag that publishes other data (needs `Release` store / `Acquire` load); `Release` on a load or `Acquire` on a store (degrades to `Relaxed`); a counter that is only ever read for statistics with `SeqCst` (fine, but `Relaxed` is the usual choice with a comment). [std::sync::atomic::Ordering]
- **Globals: `OnceLock`/`LazyLock` (1.80) over `lazy_static!`/`once_cell` and over `static mut`.** Signal: new `lazy_static!`, `once_cell::sync::Lazy`, or `static mut X: Option<T>`; a `LazyLock` initialiser that can panic (the lock is poisoned forever and every access panics). [std::sync::LazyLock; Edition guide static-mut-references]
- **`Arc`/`Rc` cycles, `Arc<T>` of non-`Send + Sync`, interior-mutable `const`.** Signal: `Arc<RefCell<_>>`, `Arc<Rc<_>>`; `const M: Mutex<..>` / `const C: AtomicUsize` (every use is a fresh copy, mutations vanish; use `static`). [`clippy::arc_with_non_send_sync` (suspicious); `clippy::declare_interior_mutable_const` (suspicious), `borrow_interior_mutable_const` (style)]
- **Data races are UB; `Sync` means shared-reference safety.** Signal: a type `Sync` through `unsafe impl` that mutates through `&self` without a lock or atomic; `UnsafeCell` reached through `&T` from two threads. [Nomicon send-and-sync; Reference UB list]
- **Rayon misuse.** Signal: `par_iter()` inside an async task (it blocks the worker); nested `rayon` pools; `par_iter` over tiny collections with `Mutex` contention inside the closure. [ryhl.io async-what-is-blocking]

### 3.6 Edition 2024 and modern idioms

Apply when `edition = "2024"` (Rust 1.85+), or when the diff migrates to it.

- **`unsafe extern` blocks with honest `safe`/`unsafe` qualifiers.** Signal: `extern "C" {` without `unsafe` (hard error in 2024); `pub safe fn strlen(..)` or any `safe` on an item with pointer preconditions; a migration that ran `cargo fix --edition` and marked everything `unsafe` without reviewing signatures (the lint does not check them). [Edition guide unsafe-extern; `missing_unsafe_on_extern`]
- **`#[unsafe(no_mangle)]`, `#[unsafe(export_name)]`, `#[unsafe(link_section)]` with a SAFETY comment.** Signal: the bare attribute forms. [Edition guide unsafe-attributes; `unsafe_attr_outside_unsafe`]
- **No references to `static mut`.** Signal: `&STATIC_MUT`, methods on it, `format!` of it. Deny by default in 2024; rewrite (atomics, `Mutex`, `LazyLock`, `&raw`). [Edition guide static-mut-references; `static_mut_refs`]
- **`unsafe_op_in_unsafe_fn` warnings are not silenced.** Signal: `#![allow(unsafe_op_in_unsafe_fn)]` added to make a migration compile. [Edition guide unsafe-op-in-unsafe-fn]
- **RPIT captures every in-scope lifetime; `use<..>` to narrow.** Signal: `fn f<'a>(x: &'a T) -> impl Iterator<Item = U>` that callers need to outlive `'a` (2024 captures `'a`; add `+ use<>` or `use<U>`); `impl_trait_overcaptures` suggestions accepted blindly (each `use<..>` is API); argument-position `impl Trait` that must be named to appear in `use<..>` (changes the signature, callers can turbofish). The `Captures<..>` and `T: 'a` tricks can be deleted. [Edition guide rpit-lifetime-capture]
- **`if let` scrutinee temporaries drop before `else`; tail-expression temporaries drop before locals.** Signal: code migrated from 2021 that relied on a lock or `Ref` living into `else` (now released, which is usually the fix, but check intent); `{ &String::from("x") }.len()` patterns (now a compile error; bind the value); `tail_expr_drop_order` warnings on types with significant `Drop`. Conversely, a `match` rewrite reintroduces the long-lived temporary. [Edition guide temporary-if-let-scope, temporary-tail-expr-scope; `if_let_rescope`, `tail_expr_drop_order`]
- **Never-type fallback is `!`.** Signal: `f()?;` on a generic `fn f<T: Default>() -> Result<T, ()>` with nothing fixing `T` (now infers `!`; write `f::<()>()?`); `never_type_fallback_flowing_into_unsafe` is deny. [Edition guide never-type-fallback; `dependency_on_unit_never_type_fallback`]
- **`Box<[T]>::into_iter()` yields `T` by value.** Signal: `boxed_slice.into_iter()` where the body expects `&T`; `boxed_slice_into_iter` warnings silenced before migrating. [Edition guide intoiterator-box-slice]
- **`gen` is reserved; `expr` fragments match `const {}` and `_`.** Signal: an identifier `gen` (needs `r#gen`); a `macro_rules!` whose `$e:expr` arms now accept `_` or `const` blocks unexpectedly (use `expr_2021`); metavariables with no fragment specifier (hard error). [1.85 blog; `keyword_idents_2024`]
- **`std::env::set_var`/`remove_var` are `unsafe`.** Signal: `unsafe { env::set_var(..) }` added by `cargo fix` with the `// TODO: Audit` comment left in; any call from multithreaded code (tests run in parallel by default). [Edition guide newly-unsafe-functions; `deprecated_safe_2024`]
- **Resolver 3 and MSRV-aware resolution.** Signal: a virtual workspace that sets `edition = "2024"` on members but no `resolver = "3"` in `[workspace]`; `rust-version` absent so the resolver has nothing to honour; a CI "latest deps" job without `CARGO_RESOLVER_INCOMPATIBLE_RUST_VERSIONS=allow`. [Edition guide cargo-resolver; Cargo CI guide]
- **Match ergonomics reservations.** Signal: `rust_2024_incompatible_pat` warnings; explicit `ref`/`mut`/`&` inside a pattern that is already borrowing by default. [1.85 blog; `rust_2024_incompatible_pat`]
- **Modern std over crates and hand-rolled code (any edition, MSRV permitting).** Signal: `lazy_static`/`once_cell` (→ `LazyLock`/`OnceLock`, 1.80/1.70); `async_trait` where no dyn is needed (→ async fn in traits, 1.75); `let x = if let .. else { return }` (→ `let else`, 1.65); `#[cfg_attr(rustfmt, rustfmt_skip)]` (→ `#[rustfmt::skip]`); `#[allow(lint)]` where `#[expect(lint)]` (1.81) would catch the day it stops firing; `allow` without `reason =`. [std docs; Reference diagnostics; `clippy::allow_attributes`, `allow_attributes_without_reason` (restriction), `clippy::deprecated_cfg_attr` (complexity)]
- **Async closures (1.85).** Signal: `|x| async move { .. }` returning a future that borrows from the closure's captures (now expressible as `async |x| { .. }` with `AsyncFn*` bounds). [1.85 blog]
- **Rustdoc merged doctests (2024).** Signal: a doctest relying on `Location::caller()` line numbers or process-global state that now shares a binary with other doctests (mark it `standalone_crate`). [rustdoc documentation-tests]

### 3.7 Cargo, features and dependencies

- **`Cargo.lock` is committed, for libraries too.** Signal: `Cargo.lock` in `.gitignore` of a library; a PR that deletes it. Why: the 2023 guidance dropped the binary/library split; determinism for bisecting, CI and MSRV checks; test latest deps with a scheduled job or Dependabot/Renovate instead. [blog committing-lockfiles; Cargo FAQ; Cargo CI guide]
- **Features are additive; `std` not `no-std`; no mutually exclusive features.** Signal: a feature that removes functionality or changes behaviour; names `no-*`, `not-*`, `use-*`, `with-*`, `*-support`; two features that cannot be enabled together without a `compile_error!`; a feature removed or moved out of `default` in a minor release (major). [Cargo features; C-FEATURE; `clippy::negative_feature_names`, `redundant_feature_names` (cargo)]
- **`default-features = false` and `dep:` for optional dependencies.** Signal: a heavy dependency pulled with defaults when the crate uses one feature (`tokio = "1"` needing only `rt`); an optional dependency exposed as an implicit feature when `dep:` would hide it; a workspace dependency whose member sets `default-features = false` while the workspace entry does not (ignored before 2024/1.99). [Cargo features; Cargo workspaces]
- **Workspace inheritance is used where it exists.** Signal: a member adding `serde = "1.0.200"` when `[workspace.dependencies]` has `serde`; a member hard-coding `edition`/`license`/`rust-version` that `[workspace.package]` provides; `[lints]` duplicated instead of `workspace = true`. [Cargo workspaces]
- **`rust-version` present and true; MSRV bumps are called out.** Signal: no `rust-version` in a published crate; a diff using an API newer than it; a bump without a changelog line (possibly-breaking, usually treated as minor). CI should run `cargo hack check --rust-version`. [Cargo manifest; Cargo semver; Cargo CI guide]
- **Version requirements: bare caret, no `*`, no artificial upper bounds, no `=`.** Signal: `foo = "*"` (crates.io rejects), `foo = ">=2.0, <2.4"`, `foo = "~1.2"`, `foo = "=1.2.3"` in a library. Why: caps make resolution fail for other users; pin in `Cargo.lock` instead. [Cargo specifying-dependencies; Cargo FAQ; `clippy::wildcard_dependencies` (cargo)]
- **Git and path dependencies cannot be published without `version`.** Signal: `{ git = ".." }` or `{ path = ".." }` in a crate without `publish = false` and without a `version` beside it; a `git` dep pinned to `branch` rather than `rev`/`tag` (floats). [Cargo specifying-dependencies]
- **`publish = false` on internal crates; metadata on public ones.** Signal: a workspace member with a `version` and no `publish = false` that is not meant for crates.io; a public crate missing `description`, `license` (SPDX, `MIT OR Apache-2.0` is the ecosystem default), `repository`, `keywords`, `categories`, `readme`. [Cargo manifest; C-METADATA, C-PERMISSIVE; `clippy::cargo_common_metadata` (cargo)]
- **`[profile]` changes are root-only and reasoned.** Signal: `[profile.*]` in a member (ignored); `panic = "abort"` added without noting tests ignore it and `catch_unwind` stops working; `overflow-checks = true` in release or `debug-assertions` changed silently; `lto = "fat"` + `codegen-units = 1` added to a dev loop; `strip` that removes the symbols the panic hook needs. [Cargo profiles]
- **`build.rs` stays local, deterministic and cheap.** Signal: network access (`curl`, `git clone`, `reqwest`) in a build script; writing outside `OUT_DIR`; `cfg!(target_os)` instead of `CARGO_CFG_TARGET_OS` (checks the host); no `cargo::rerun-if-changed` (reruns on every file change); compiling a vendored C library without `cc` and without a `pkg-config`/system fallback. [Cargo build-scripts]
- **Supply chain: `cargo deny`, `cargo audit`, `cargo vet` where configured.** Signal: a new dependency not covered by `deny.toml` licences (check the allow-list), from a git source when `[sources]` restricts to crates.io, duplicating an existing crate at another major (`[bans] multiple-versions`), or unmaintained/yanked per RustSec; a new dependency without a `cargo vet` audit or exemption; a tiny dependency that replaces ten lines. [cargo-deny checks; RustSec; cargo-vet; `clippy::multiple_crate_versions` (cargo)]
- **`unsafe` in dependencies is a review item, not a veto.** Signal: a new dependency with `unsafe` for no clear reason (`cargo geiger`, or read it) when the project forbids unsafe locally; a `-sys` crate linking a system library. [C-STABLE for public deps; Principles: a dependency that changes the licence story is a design change]
- **`#![deny(warnings)]` in source is an anti-pattern; deny in CI.** Signal: `#![deny(warnings)]` or `#![deny(clippy::all)]` in `lib.rs`. Why: a new rustc or a deprecation in a dependency breaks every downstream build. Use `CARGO_BUILD_WARNINGS=deny`/`RUSTFLAGS=-Dwarnings` in CI or deny a named list. [patterns/anti_patterns/deny-warnings; Cargo CI guide]
- **`#![forbid(unsafe_code)]` where the crate has no unsafe; never downgraded quietly.** Signal: removal of `forbid(unsafe_code)` or `unsafe_code = "forbid"` to admit one block; `#[allow(unsafe_code)]` on a module. [`unsafe_code` (rustc)]
- **`[lints]` table priorities.** Signal: `pedantic = "warn"` and `module_name_repetitions = "allow"` at the same priority (undefined which wins); fix with `{ level = "warn", priority = -1 }` on the group. [Cargo manifest; `clippy::lint_groups_priority` (correctness)]
- **Public dependencies of a 1.0 crate are 1.0.** Signal: a `0.x` crate's type in the public API of a `1.x` crate (including through a `From` impl on a public error). [C-STABLE]

### 3.8 Documentation

- **Every public item has a doc comment; the first line stands alone.** Signal: `pub fn`/`pub struct`/`pub mod` without `///`; a first paragraph longer than a sentence (rustdoc uses it as the summary); type information repeated in prose. Enable `#![warn(missing_docs)]` in libraries. [rustdoc how-to-write-documentation; `missing_docs` (rustc, allow); `clippy::too_long_first_doc_paragraph` (nursery)]
- **`# Errors` on every public `-> Result`, `# Panics` on every function that can panic, `# Safety` on every `unsafe fn`/trait.** Signal: a `pub fn .. -> Result` with no `# Errors` section; `unwrap`/indexing/`assert!` in a public fn with no `# Panics`; a `# Safety` section on a safe fn. Panics caused by caller-supplied closures need not be listed. [C-FAILURE; `clippy::missing_errors_doc`, `missing_panics_doc` (pedantic), `missing_safety_doc` (style), `unnecessary_safety_doc` (restriction)]
- **`# Examples` that compile, use `?`, and show why.** Signal: a new public type or function with no example; examples using `unwrap()` ("unwrapping should be a conscious decision"); examples that need `fn main()` written out (rustdoc wraps them); ```` ```ignore ```` without a reason in parentheses; ```` ```no_run ```` on something that could run; ```` ```compile_fail ```` without an error code (breaks when rustc improves); `#[test]` inside a doctest (silently skipped). [C-EXAMPLE, C-QUESTION-MARK; rustdoc documentation-tests; `clippy::needless_doctest_main` (style), `clippy::test_attr_in_doctest` (suspicious)]
- **Crate-level `//!` docs are the front page: what it is, where it fits, one real example, the feature list.** Signal: `lib.rs` with no `//!`; features undocumented (which are stable, which optional dependency each enables). [C-CRATE-DOC; rustdoc how-to-write-documentation; Cargo features "documentation and discovery"]
- **Intra-doc links, not bare names or absolute URLs to docs.rs.** Signal: `the `Foo` type` without `[`Foo`]`; `[Foo](https://docs.rs/..)`; `['foo']` (typo for backticks); identifiers outside backticks (`snake_case`, `Path::to`). Build with `RUSTDOCFLAGS=-Dwarnings` to catch broken links. [C-LINK; `rustdoc::broken_intra_doc_links`; `clippy::doc_markdown` (pedantic), `clippy::doc_link_with_quotes` (pedantic)]
- **`#[doc(hidden)]` for implementation details; `pub(crate)` rather than `pub` + hidden.** Signal: a public `From<PrivateError>`; `__private` modules not hidden; macros' support items exposed. [C-HIDDEN]
- **README and `lib.rs` docs do not drift.** Signal: README example differs from the `//!` example; `#![doc = include_str!("../README.md")]` is the usual fix (check the README's code fences are rustdoc-valid or marked ```` ```text ````). [C-CRATE-DOC]
- **Doc comment hygiene.** Signal: `///!` (meant `//!`), empty `///`, lazy list continuations, `#[doc(include)]` without `cfg(doc)`. [`clippy::suspicious_doc_comments`, `empty_docs` (suspicious), `doc_lazy_continuation` (style)]
- **Release notes / CHANGELOG record every significant change, with `since` on deprecations.** Signal: a public change without a changelog entry; `#[deprecated]` without `since` and `note`, or with a non-semver `since`. [C-RELNOTES; `clippy::deprecated_semver` (correctness)]
- **Document `#[must_use]`, `#[non_exhaustive]`, sealedness and MSRV policy in prose.** Signal: a sealed trait with no sentence saying so; a `#[non_exhaustive]` enum whose docs do not warn about the wildcard arm. [C-SEALED; Reference type_system]

### 3.9 Tests

- **Unit tests in `#[cfg(test)] mod tests` beside the code; integration tests in `tests/`; shared helpers in `tests/common/mod.rs`.** Signal: `#[test]` outside a `cfg(test)` module (compiles into the artifact); `tests/common.rs` (runs as an empty test crate); test-only dependencies in `[dependencies]` instead of `[dev-dependencies]`; a binary-only crate with integration tests that cannot import it (move logic to `lib.rs`). [Book ch11-03; `clippy::tests_outside_test_module` (restriction)]
- **`#[should_panic(expected = "..")]`, never bare `#[should_panic]`.** Signal: `#[should_panic]` without `expected`; `should_panic` on a `-> Result` test (not allowed). Why: a bare one passes on any panic, including an unrelated bug. Prefer `Result`-returning tests with `assert!(r.is_err())` or matching the error variant. [Book ch11-01; Reference testing; `clippy::should_panic_without_expect` (pedantic)]
- **Assertions compare values and say why.** Signal: `assert!(a == b)` (use `assert_eq!` for the `left`/`right` diff); `assert!(cond)` with no message where failure output would not reveal the value; `assert_eq!(result.is_ok(), true)` (`assert!(matches!(..))` or `unwrap()` the result for the message); `assert!(x.is_err())` with no check of which error. (`assert_eq!` arguments are `left`/`right`, so order is a project convention, not a rule.) [Book ch11-01; `clippy::missing_assert_message` (restriction, exempts tests by default), `clippy::bool_assert_comparison` (style)]
- **`Result<(), E>`-returning tests use `?`; `unwrap` in tests is fine.** Signal: a test that `unwrap()`s a dozen `Result`s where `-> anyhow::Result<()>` with `?` would read better; `clippy::unwrap_used` complaints in tests when `allow-unwrap-in-tests = true` is the project's setting. [Book ch09-03 ("in tests, unwrap is exactly what should happen"); clippy lint_configuration]
- **`#[ignore]` always carries a reason.** Signal: `#[ignore]` with no `= "reason"`; an ignored test that nobody runs in CI (`--include-ignored` nightly job). [Reference testing; `clippy::ignore_without_reason` (pedantic)]
- **Tests do not depend on order or on `--test-threads=1`.** Signal: a `Justfile`/CI line adding `-- --test-threads=1`; tests sharing a global (`static mut`, `env::set_var` (unsafe in 2024, races parallel tests), fixed ports, fixed temp paths); a `serial_test` attribute added without explanation. Why: libtest runs tests in parallel in one process; the shared state is the bug. (A project that serialises tests deliberately for container contention, as ankka does, documents the reason.) [Book ch11-01; Edition guide newly-unsafe-functions; nextest how-it-works (process-per-test isolates, but hides the dependency)]
- **Doc tests are tests.** Signal: a doctest marked `ignore` to make CI green; `no_run` on an example that could run; a crate with `doctest = false` and no reason. [rustdoc documentation-tests; Cargo targets]
- **Async tests use the right runtime flavour.** Signal: `#[tokio::test]` (current-thread) testing code that must be `Send` or that deadlocks only under the multi-thread scheduler (use `flavor = "multi_thread", worker_threads = N`); timing tests sleeping real seconds instead of `start_paused = true`; a runtime built by hand per test when the attribute suffices. [Tokio attr.test]
- **Property tests and snapshot files are committed.** Signal: `proptest!` with `proptest-regressions/` ignored in git (the found minimal failures are the regression suite); `insta` snapshots (`*.snap`) with `.snap.new` committed by mistake or `INSTA_UPDATE=always` in CI. [proptest intro (strategies and shrinking); project convention for insta]
- **Unsafe code has a Miri run; FFI and I/O are outside Miri.** Signal: unsafe-heavy module with no `cargo +nightly miri test` in CI and no `#[cfg_attr(miri, ignore)]` strategy for tests that need FFI/network; Miri enabled but every unsafe test ignored under it. [Miri README]
- **Overflow and debug assertions are tested in both profiles when they matter.** Signal: arithmetic code whose tests pass only because debug overflow checks panic (or only because release wraps); no `cargo test --release` for a crate whose `release` profile sets `overflow-checks = false` and whose correctness depends on `checked_*`. [Book ch03-02; Cargo profiles]
- **Benchmarks are not tests.** Signal: `#[bench]` (nightly only) in a stable crate; `criterion`/`divan` benches in `tests/` instead of `benches/` with `harness = false`; benchmark results asserted in tests. [Cargo targets]
- **Mocks via traits, not globals.** Signal: `mockall`'s `#[automock]` on a trait that is also sealed or not dyn-compatible; test doubles implemented by `cfg(test)` branches inside production functions (prefer injecting the trait). [C-OBJECT]
- **`#[cfg(test)]` helpers do not leak into the build; test-only `pub` is `pub(crate)` or `#[doc(hidden)]`.** Signal: `pub fn test_helper()` in `lib.rs` without `cfg(test)`; `#[cfg(test)]` on a `pub use` that integration tests then cannot see (integration tests are external; expose a `test-util` feature instead). [Book ch11-03]

### 3.10 WebAssembly targets

Apply when the crate builds for `wasm32-unknown-unknown` (browser/wasm-bindgen), `wasm32-wasip1`, or
`wasm32v1-none`.

- **No threads, no filesystem, silent stdout on `wasm32-unknown-unknown`.** Signal: `std::thread::spawn` (panics at runtime), `std::fs` (always errors), `println!` for user output (does nothing; use `web_sys::console` or `log` + a wasm logger), `std::time::Instant` (panics on unknown-unknown; use `js_sys::Date`/`web_time`), `std::env`, `std::net`. Why: the target imports nothing from the host. Gate with `#[cfg(target_arch = "wasm32")]` or `all(target_family = "wasm", target_os = "unknown")`; there is no cfg for browser vs non-browser. [rustc platform-support wasm32-unknown-unknown]
- **Panics abort; install `console_error_panic_hook`.** Signal: `catch_unwind` relied upon (default `-Cpanic=abort`; unwinding needs nightly `-Zbuild-std`); no `console_error_panic_hook::set_once()` in the init path (otherwise panics show as "RuntimeError: unreachable executed"); `Result`-based error paths replaced by `unwrap` "because wasm". [rustc platform-support; rustwasm debugging]
- **Randomness needs an explicit backend.** Signal: `rand`/`uuid`/`getrandom` in a wasm build without the `getrandom` `wasm_js` feature (and `RUSTFLAGS=--cfg getrandom_backend="wasm_js"` for 0.3) in the **binary/cdylib**; the feature enabled in a **library** (breaks non-web wasm consumers). [getrandom docs]
- **Size is a feature: `opt-level = "s"`/`"z"`, `lto = true`, `codegen-units = 1`, `wasm-opt`.** Signal: a wasm `cdylib` with default release profile; `format!`/`to_string` in hot paths (pulls in formatting machinery); `panic!` with formatted messages everywhere; generics exploded across many types where `dyn` would emit one copy; `debug = true` left on in release unless stack traces are wanted. Measure with `twiggy`. [rustwasm code-size; Cargo profiles]
- **Allocation is explicit.** Signal: default `dlmalloc` where size matters (consider `talc`/`lol_alloc`; `wee_alloc` is unmaintained, do not recommend it); unbounded `Vec` growth in a long-lived page (no OS to reclaim); `#![no_std]` crate without `#[global_allocator]` when it allocates. [rustwasm code-size]
- **`#[wasm_bindgen]` boundaries: what crosses, what copies, what throws.** Signal: exported `fn` with lifetimes or generics (unsupported); `pub String`/`Vec` fields on an exported struct without `#[wasm_bindgen(getter_with_clone)]`; returning `Result<T, E>` where `E` is not `Into<JsValue>` (`JsError`, `String`, or `#[derive(thiserror)]` + `From` impl); large `Vec<u8>` returned by value when a `&[u8]`/`Uint8Array` view would avoid the copy; `Box<[T]>`/`Vec<T>` of non-number types (copied through JS arrays). [wasm-bindgen exported-rust-types; wasm-bindgen result]
- **JS-owned Rust objects must be `free()`d.** Signal: exported structs handed to JS in a loop with no `free()` call on the JS side and no `FinalizationRegistry` reliance documented; `&mut self` methods called from JS while another borrow is live (runtime "recursive use of an object" error). [wasm-bindgen exported-rust-types]
- **Target features and `atomics`.** Signal: `#[target_feature(enable = "simd128")]` without a `cfg` fallback; code assuming `atomics`/shared memory (not in the default feature set; needs `-Ctarget-feature=+atomics,+bulk-memory` and `-Zbuild-std`); `wasm32v1-none` chosen for `no_std` but code uses `bulk-memory`/`sign-ext`. [rustc platform-support]
- **`no_std` compatibility for `wasm32v1-none` and embedded-style wasm.** Signal: `std::` paths in a crate with a `std` feature (use `core::`/`alloc::` and `#[cfg(feature = "std")] extern crate std;`); a `no_std` feature instead of a `std` feature (non-additive). [Cargo features; C-FEATURE; `clippy::std_instead_of_core` (restriction)]
- **Time, sleep and async on wasm.** Signal: `std::thread::sleep` in wasm (blocks the only thread, or panics); `tokio` runtime features (`rt-multi-thread`) in a wasm target (use `wasm-bindgen-futures::spawn_local`, `gloo-timers`); futures that must be `Send` on native but `!Send` on wasm handled with a `cfg`-gated trait alias. [rustc platform-support; Tokio spawn_blocking (no blocking pool on wasm)]
- **Testing on wasm.** Signal: `#[test]` only, with no `wasm-bindgen-test` or `wasm32-wasip1` + `wasmtime` run for the code that is cfg-gated to wasm (so it is never compiled in CI); `cargo test --target wasm32-unknown-unknown` without a runner configured in `.cargo/config.toml`. [rustc platform-support ("test with wasm32-wasip1 instead")]

## 4. Severity hints

**Blocking (request changes).**
- Any soundness hole: safe `pub fn` that can cause UB; `&mut` from `&`; references to `static mut`; `unsafe impl Send/Sync` with an unbounded `T` or a `!Send` field; transmute between `repr(Rust)` types; uninitialised memory read; `set_len` before init; unwinding across `extern "C"`; wrong FFI signature or missing `repr(C)`; `Pin` contract broken. (Reference UB list, Nomicon.)
- Data races and deadlocks waiting to happen: a `std` guard or `RefCell` borrow across `.await`; blocking I/O or `sleep` on an async worker; `RwLock` reader re-entry under writers; a Tokio `Mutex` where a lock is held across a long operation on a single-threaded runtime.
- Panics on caller-controlled input in a **library** (`unwrap`, `expect`, `v[i]`, `&s[a..b]`, `assert!`), or any panic in `Drop`. In a binary the same code is should-fix unless it is the top-level error edge.
- Silently discarded errors on I/O or state changes (`let _ = w.write_all(..)`, ignored `write`/`read` counts).
- Semver breaks in a published crate without a major bump: removed/renamed public items, new required trait method, new variant on an exhaustive enum, new field on an all-public struct, removed feature, raised MSRV without a note.
- Edition-2024 hard errors in a 2024 crate (`extern` without `unsafe`, bare `#[no_mangle]`, `&STATIC_MUT`) and behaviour changes accepted without review (`Box<[T]>::into_iter`, `if let` scope, tail temporaries, RPIT overcapture).
- Build and supply chain: `build.rs` touching the network or writing outside `OUT_DIR`; a dependency that fails `cargo deny` (licence, banned, advisory, disallowed source); `*` versions; git dependency in a publishable crate without `version`; removal of `forbid(unsafe_code)`.
- WebAssembly: `thread::spawn`, blocking sleep, `std::fs`, or `getrandom` without a backend on a wasm target (runtime panic or link failure).

**Should fix before merge.**
- Missing `// SAFETY:` comments and `# Safety`/`# Errors`/`# Panics` sections; `unsafe` without a test that Miri runs.
- `anyhow`/`Box<dyn Error>` in a library's public API; error enums without `#[non_exhaustive]`, `source()`, or `Error + Send + Sync + 'static`; `()` as an error type; `map_err` that drops the cause.
- `Arc<Mutex>`/`Rc<RefCell>` where ownership could be clearer; `Rc<Mutex>`; strong cycles; unbounded channels on external input; detached tasks without a stated reason; `Relaxed` ordering without a comment.
- Inconsistent `Ord`/`PartialOrd`/`Eq`/`Hash`; `#[derive(Copy)]` on large types; missing `Debug`/`Clone`/`Default`/`PartialEq` on public data types; `Deref` abuse; `bool` parameters that should be enums; `&String`/`&Vec` parameters; `impl Into` written by hand.
- Overflow-prone arithmetic on unbounded values; `as` casts that can truncate; `partial_cmp().unwrap()`; `==` on floats.
- `#![deny(warnings)]` in source; missing `rust-version`; `Cargo.lock` ignored; `[profile]` in a member; features that are not additive; `default-features` left on for heavy deps; missing `publish = false`.
- Tests: bare `#[should_panic]`, `#[ignore]` without a reason, order-dependent tests, `--test-threads=1` as a crutch, `env::set_var` in parallel tests, `Result` tests that `unwrap` everything, missing doctest for a new public item.
- `dbg!`, `println!` in libraries, `todo!()` in shipped paths, `#[allow]` without `reason`.
- Wasm: no `console_error_panic_hook`, default release profile for a size-sensitive module, `getrandom` feature enabled in a library.

**Nit (mention once, do not block).**
- Naming conventions (`get_` prefix, `to_`/`as_`/`into_` mismatch, module name repetition, variant name repetition), `matches!`/`let else`/`if let` rewrites, `mem::take` over `mem::replace`, `unwrap_or_default`, `Rc::clone(&x)` spelling, `clone_on_copy`, redundant clones the optimiser removes, `#[inline]` placement, `#[must_use]` candidates, `const fn` candidates, `unused_async`, lifetime elision, `wildcard_imports` outside preludes and test modules, doc Markdown backticks, `too_many_arguments` at the threshold, `Option<Option<T>>` in private code, `LinkedList`, `large_futures` below the threshold, rustfmt-level layout (never comment if rustfmt runs).

## 6. Open questions and disagreements

- **`anyhow` in libraries.** The crate's own docs say "applications"; the API guidelines want a typed `Error + Send + Sync + 'static`. Reasonable disagreement: an internal workspace library consumed only by the workspace's binaries can use `anyhow` without harm, and many do. Rule of thumb this checklist applies: typed errors for anything with `publish` not `false`, or anything another team matches on; `anyhow` otherwise, but never leaking `anyhow::Error` through a trait object boundary that callers must downcast. `Box<dyn Error + Send + Sync>` sits between: fine at an application edge, poor in a library.
- **`unwrap` policy.** The Book sanctions `unwrap`/`expect` in examples, prototypes, tests, and where the programmer has information the compiler lacks; Clippy puts `unwrap_used` in `restriction` precisely because teams disagree. Positions range from "never, use `?`" (deny `unwrap_used` + `expect_used`, allow in tests) to "`expect` with an invariant message is the documentation". This checklist treats `unwrap` on caller-controlled data in a library as blocking, `expect("<invariant>")` on a provably-true fact as acceptable, and `unwrap` in binaries' `main`-adjacent code as a should-fix only when a user could trigger it.
- **`dyn Trait` vs generics.** The guidelines list the trade-offs and decline to pick; `clippy::impl_trait_in_params` is restriction-only. Projects differ: binary-size-sensitive (wasm, embedded, CLI) teams prefer `dyn`; library and hot-path code prefers generics. Review for the *reason* being stated, not for the choice.
- **`#[must_use]` breadth.** `must_use_candidate` is pedantic and the lint itself says "many false positives". Some teams apply it to every pure fn; others only to builders and `Result`-like types. Follow the crate's existing practice.
- **`Cargo.lock` for libraries.** The 2023 change says "do what is best"; the default is now to commit. A library whose CI deliberately tests floating dependencies may still ignore it, provided a latest-deps job exists either way.
- **Who owns the `Send` bound on async traits.** The 1.75 announcement is explicit that the trait author decides and callers cannot add it later; `trait-variant` generates both. Whether to publish only the `Send` variant (simpler, excludes single-threaded executors) or both is a judgement call per crate.
- **`std::sync::Mutex` vs `parking_lot`.** `parking_lot` has no poisoning, smaller guards and fairer locking; `std` is dependency-free and poisoning is a feature for some. Both are defensible; flag only mixing them for the same data or holding either across `.await`.
- **`Relaxed` for counters.** Widely accepted for statistics counters that publish nothing; some reviewers want `SeqCst` by default to avoid reasoning. The std docs do not adjudicate. This checklist asks for one comment line.
- **`#![deny(warnings)]`.** The anti-pattern page and Cargo's CI guide both prefer denying in CI; a few projects keep it in source for binaries they rebuild themselves. Accept it in a binary with a pinned `rust-toolchain.toml`; reject it in a library.
- **Restriction lints as policy.** Clippy warns against enabling the whole group (`blanket_clippy_restriction_lints`). Which individual ones a project adopts (`indexing_slicing`, `arithmetic_side_effects`, `as_conversions`) is a per-crate decision that should live in `[lints.clippy]`, not in review comments.
- **Graphemes.** Whether UI code must segment by grapheme cluster (needs `unicode-segmentation`) or `chars()` suffices depends on the domain; the Book only says the two differ.
- **Edition migration pace.** Whether to adopt 2024 immediately (new rules above) or stay on 2021 until the MSRV floor allows 1.85 everywhere; `rust-version` decides. A crate on 2021 with `rust-version = "1.85"` has no reason not to migrate.
- **Allocator on wasm.** `wee_alloc` was the book's recommendation and is now unmaintained with known issues; the code-size page still names it. Treat the allocator choice as a measured decision, not a rule.
