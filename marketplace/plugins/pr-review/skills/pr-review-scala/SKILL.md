# Reviewing Scala

Scala reviews most often miss what the compiler cannot see: actor state written from a `Future`
callback, blocking on the wrong dispatcher, a side effect replayed from an event handler, a codec
derived twice, `.get` on an empty `Option`, `==` between two arrays. The diff compiles and the
tests are green. Apply the groups in this order: concurrency and actors, serialization, types and
totality, error handling, collections, tests, build, API design, then Scala 3 idioms and surface
style. The first four groups are usually blocking; the last is usually a nit the formatter owns.

## Before reading the code

Read `scalaVersion` in `build.sbt` (`ThisBuild / scalaVersion := "3.x.y"`) and `runner.dialect` in
`.scalafmt.conf` first, then confirm against the syntax in the diff.

| Evidence | Dialect | What changes for the review |
|---|---|---|
| `scalaVersion := "3.*"`, `runner.dialect = scala3`; `enum`, `given`, `using`, `extension`, `export`, `opaque type`, `derives`, `then`/`do`, `end x`, `object Foo:`, `List[?]`, `xs*`, `import a.*`, `A \| B`, `@main`, top-level `def` | Scala 3 | `(Scala 3)` items apply; `implicit`, `_` wildcards, `: _*`, `private[this]`, `A with B` are leftovers to flag; refutable patterns and nonlocal returns warn from 3.2, the old spellings from 3.4 |
| `scalaVersion := "2.13.*"`, `runner.dialect = scala213`; `implicit val/def/class`, `import a._`, `{b => c}`, `xs: _*`, `List[_]`, `package object`, `A with B` | Scala 2.13 | skip `(Scala 3)` items; `private[this]` still means something; `-Xlint:infer-any` exists; refutable `for` patterns filter silently |
| `-Xsource:3` in `scalacOptions`, `runner.dialect = scala213source3` | 2.13 adopting Scala 3 syntax | `?`, `*` imports and `case` generators parse; a private constructor hides `apply`/`copy` |
| `// Generated by the Scala Plugin for the Protocol Buffer Compiler`, a `target/` or `src_managed/` path | generated | do not review line by line |
| `build.sc`/`build.mill`, `pom.xml` with `scala-maven-plugin`, Gradle `scala` plugin | Mill, Maven, Gradle | the sbt items under Build map onto that tool's equivalents |

Then read the tooling, so the review never repeats it: `scalacOptions` in `build.sbt` or
`project/*.scala` (`-Werror`, `-Wunused:*`, `-Wvalue-discard`, `-Wnonunit-statement`,
`-Wsafe-init`, `-source:future`, `-language:strictEquality`, `-Yexplicit-nulls`, `-Xlint`);
`.scalafmt.conf` (`rewrite.rules`, `rewrite.scala3.*`; a project that leaves `SortModifiers` out
usually did so deliberately, so do not ask for it); `.scalafix.conf` and `project/plugins.sbt` (scalafix rules,
`wartremoverErrors`, MiMa); `application-test.conf` (`pekko.actor.serialize-messages`);
`.githooks/` and CI for `scalafmtCheckAll` and `mimaReportBinaryIssues`.

## Checklist

Each item: rule, the signal or diff shape, why, source. `(Scala 3)` means only on a Scala 3 build.

### Concurrency, Futures and actors

- **Actor state is touched only from its own message handler.** Signal: `Future { state = … }`,
  `onComplete { … context.self … }`, `ask(...).foreach { state = _ }`, `sender()` in a classic
  callback. Why: no happens-before; `context.pipeToSelf`/`context.ask` deliver a message. [Pekko JMM]
- **No blocking on a shared dispatcher.** Signal: `Thread.sleep`, JDBC, `Await`, synchronous HTTP
  inside `Future { }`, `Behaviors.receive` or `onComplete`; `ExecutionContext.Implicits.global` in
  service code. Why: it starves every other actor; use `DispatcherSelector.blocking()`. A runtime on
  virtual threads may document blocking `invoke` as allowed; read its rules first. [Pekko dispatchers]
- **`Await.result` only at the edges.** Signal: `Await.result(f, Duration.Inf)` on a production path
  or inside a munit test body. Why: "strongly discouraged" for deadlocks; a test returns the
  `Future` and munit awaits it under `munitTimeout`. [futures overview, munit tests]
- **Callbacks do not close over mutable state.** Signal: `var total`; `f1.foreach(total += _)`;
  `f2.foreach(total += _)`. Why: order is undefined and `+=` is not atomic; fold with `zip`,
  `Future.sequence` or a for-comprehension. [futures overview]
- **Messages, events and state are immutable.** Signal: `var`, `mutable.Buffer`, `ListBuffer` or
  `Array` in a `case class` sent or persisted. Why: a shared mutable message is a race, and a mutated
  field corrupts any `Set` or `Map` holding the value. [Pekko JMM, Databricks]
- **Every ask has a timeout and the receiver always replies.** Signal: no `Timeout` in scope,
  `system.ignoreRef` as `replyTo`, a branch that neither replies nor fails. Why: the asker waits
  for the timeout; inside an actor use `context.ask`, never `AskPattern`. [Pekko interaction-patterns]
- **Validation in the protocol, failures crash, restarts bounded.** Signal: `try/catch` to "keep
  the actor alive"; `supervise(...).onFailure(restart)` without `withLimit`; state created outside
  `Behaviors.setup`; `watch` with no `Terminated` case. Why: Typed stops by default, rejections are
  `StatusReply.error`, an unhandled `Terminated` is a `DeathPactException`. [Pekko fault-tolerance]
- **Per-session children stop themselves.** Signal: a spawned child or aggregator with no `stop`
  path and no receive timeout. Why: a missed case leaks the actor. [Pekko interaction-patterns]
- **Event handlers are pure; side effects in `thenRun`; all state in `State`.** Signal: logging,
  publishing, a `var` outside the state class or a remote call inside an `EventSourcedBehavior` event
  handler. Why: it replays on recovery and fields outside `State` vanish on restart. [Pekko persistence]
- **No `context.self` in a message to a sharded entity.** Signal: `ctx.self` as `replyTo` to an
  entity that may passivate; an `ActorRef` in a static or long-lived collection. Why: it
  dead-letters; carry the `entityId` or an `EntityRef`. [Pekko interaction-patterns]

### Serialization and interop

- **One codec per top-level type, in the companion, as a val.** Signal: `implicit def codec[T]:
  JsonValueCodec[T] = JsonCodecMaker.make`, `inline given`, `make` inside a method. Why: silent
  duplicate codecs and multiplied bytecode; `derives` lands in the companion. [jsoniter-scala README]
- **Status-word enum codecs live in the companion.** Signal: a fieldless enum's codec defined at one
  call site. Why: every other site encodes `{"type":"Ready"}` and the wire disagrees with itself.
  [jsoniter-scala README]
- **Know the codec's null, Option and default semantics before adding a field.** Signal: an
  `Option` field whose default is not `None`; a new field without a default on a type read from old
  JSON. Why: jsoniter reads JSON `null` on an `Option` as absent and applies the default, so "none"
  cannot be said; fields without defaults are required. [jsoniter-scala README]
- **Persisted and wire types are a versioning boundary.** Signal: a renamed field, reordered enum
  cases (`ordinal` changes), a changed discriminator on a journaled or published type. Why: the event
  handler replays old JSON; evolve with manifests, `@named`, additive defaults. [Pekko serialization]
- **New messages extend the marker trait; no Java serialization.** Signal: a message or event not
  extending `CborSerializable`/`JsonSerializable`, or carrying a type the serializer cannot handle.
  Why: Java serialization is off and "highly discouraged". [Pekko serialization]
- **One version of the serialization library on the classpath.** Signal: a transitive
  `jsoniter-scala-core` at another version than the macros. Why: codecs break at runtime. [jsoniter]
- **Java-facing APIs: `Option(x)` at the boundary, no Scala-only shapes.** Signal: a Java-called API
  with default arguments, multiple parameter lists, `using` or a `trait` with concrete methods;
  `Some(javaValue)`. Why: Java cannot call them and `Some(null)` lies; add `@varargs`. [Databricks]

### Types, nulls and totality

- **Public members carry explicit result types.** Signal: `def`/`val` without a type on a public or
  `protected` member, or on any `given`/`implicit`. Why: no inferred refinements or accidental
  binary changes; Scala 3 requires it on implicits. [style/types, scalafix ExplicitResultTypes]
- **No partial accessor on a possibly-empty value.** Signal: `\.get\b` on `Option`/`Try`/`Either`
  projections, `.head`, `.last`, `.reduce(`, `.max` on a possibly-empty collection. Why: each throws
  on empty; `fold`, `getOrElse`, `headOption`, `reduceOption`, a `match`. [wartremover OptionPartial]
- **No `null` in Scala code; wrap Java nulls at the boundary.** Signal: a `null` literal, `== null`,
  a Java result used unchecked. Why: `Option(javaValue)` types the absence; under `-Yexplicit-nulls`
  `.nn` is an auditable assertion. [wartremover Null, explicit-nulls]
- **No `asInstanceOf` or `isInstanceOf`; pattern match instead.** Signal: `.asInstanceOf[`,
  `.isInstanceOf[List[String]]`. Why: casts bypass the checker and erasure makes the check cover only
  `List`; `case x: T =>` at least warns. [wartremover AsInstanceOf]
- **Inferred `Any`, `Product`, `Serializable` or `Nothing` is a lost type.** Signal: `Seq(1, "a")`,
  `if` branches of different types, a `Map` of mixed values. Why: Scala 3 has no `infer-any` lint,
  so only a reviewer sees it; ascribe the intended type. [wartremover Any]
- **Sealed hierarchies for anything matched on; leaves `final`; no catch-all.** Signal: `trait
  Command` without `sealed`; a `case class` extending it without `final`; `case _ =>` on an enum or
  sealed scrutinee. Why: only sealing gives exhaustiveness and the wildcard throws it away; a
  non-final leaf breaks `equals`/`copy`. [tour/pattern-matching, Pekko style guide]
- **`==` between unrelated types is a silent `false`.** Signal: `id == idString`,
  `optValue == value`, `someEnum == "name"`. Why: universal equality compiles anything; prefer
  `-language:strictEquality` with `derives CanEqual`. [multiversal-equality]
- **`==` on `Array` compares references.** Signal: `arr1 == arr2`; an `Array` field in a `case
  class`. Why: generated `equals`/`hashCode` use identity; `sameElements`, or `ArraySeq`/`IArray`/
  `Vector` in case classes. [wartremover ArrayEquals]
- **Numeric `==` widens and `Double` equality is fragile.** Signal: `x == 0.3` on a computed double,
  a `Map` keyed by `Double`, a NaN check with `==`. Why: `1 == 1.0` is true, `0.1 + 0.2 == 0.3` is
  false, `NaN == NaN` is false yet equal as a key. [spec §12; reviewer experience]
- **Nothing reads a `val` before it is initialised.** Signal: a trait or superclass body using an
  abstract `val`; a subclass overriding a `val` the parent reads; `val handlers = List(a, b)` above
  `val a`. Why: strict order yields `null`; parameters, `lazy val` or `def`. [FAQ initialization-order]

### Error handling

- **Expected failures in the type; exceptions for the unexpected.** Signal: a public API throwing
  for `NotFound` or validation; `Option` from a function that fails for several reasons. Why: return
  `Either[Error, A]` or a sealed result, since `None` loses the reason. [Effective Scala, Databricks]
- **Never catch `Throwable`, `Exception` or `case _ =>` blindly.** Signal: `case e: Throwable =>`,
  `case _: Exception =>`, bare `case e =>` in a `catch`. Why: `OutOfMemoryError`,
  `InterruptedException` and `ControlThrowable` must propagate, and a fatal error never completes a
  `Future`; match `NonFatal(e)`. [Effective Scala, futures overview]
- **No `.get` on a `Try`; its combinators rethrow.** Signal: `tryValue.get`,
  `getOrElse(computeThatThrows)`, `foreach` with a throwing function. Why: `get` rethrows the stored
  exception and `getOrElse`/`foreach` throw what their argument throws. [Try scaladoc]
- **Failed Futures are returned, not thrown.** Signal: `def f(): Future[A] = { if (bad) throw …;
  Future(...) }`. Why: the throw is synchronous in the caller, outside the error channel; return
  `Future.failed`. [Effective Scala]
- **`Either` and `Try` keep their error.** Signal: `.left.get`, `.right.get`, `.toOption` dropping
  the failure, `Either[Throwable, A]` where a sealed error would carry meaning. Why: the reason is
  lost where it mattered. [wartremover EitherProjectionPartial]
- **`require` for preconditions, `assert` for invariants, neither for input.** Signal: `require` on
  an HTTP body or message field. Why: a contract violation is `IllegalArgumentException`; external
  input belongs in the result type or the actor protocol. [Effective Scala, Pekko fault-tolerance]
- **`recover` only the failures you mean.** Signal: `.recover { case _ => default }`. Why: it
  swallows every non-fatal failure including bugs; match the types, `recoverWith` for an alternative.
  [futures overview]

### Collections and performance

- **`Seq` is `immutable.Seq` and defaults to `List`; index with `Vector`.** Signal: `Seq(...)` then
  `xs(i)`, `xs.length` or `:+` in a loop. Why: `List` is linear for all three, `Vector` effectively
  constant; accept `Seq[T]`/`Iterable[T]` in signatures. [performance-characteristics]
- **No appending to a `List` in a loop; `ListMap` has no good use.** Signal: `acc :+ x` on a `List`,
  `ListMap(`. Why: O(n) per append, O(n²) total; `ListMap` is linear in everything; `ListBuffer`,
  `Vector` or prepend-then-reverse. [performance-characteristics]
- **Mutable collections named at the use site, kept local.** Signal: `import
  scala.collection.mutable.Map` then bare `Map`. Why: `mutable.Map` makes it visible; confine to one
  method or one actor. [Effective Scala]
- **An `Iterator` is consumed once.** Signal: `it.size` then `it.map`, `it.toList` then
  `it.foreach`, one `Iterator` passed to two functions. Why: "never use an iterator after calling a
  method on it"; a strict collection or `duplicate`. [Iterator scaladoc]
- **`LazyList` for laziness, never `Stream`; mind memoisation.** Signal: `Stream`; a `LazyList` held
  in a `val` while traversed. Why: `Stream` is deprecated and a referenced `LazyList` retains every
  element produced; `Iterator` for one pass. [collections-migration-213]
- **Varargs take an immutable `Seq`; splice with `xs*`.** Signal: `f(array: _*)`, `f(buffer: _*)`.
  Why: 2.13 requires `immutable.Seq`; `.toSeq` or `ArraySeq.unsafeWrapArray`.
  [collections-migration-213, vararg-splices]
- **Java collections cross the boundary once.** Signal: `asScala`/`asJava` on every access;
  `JavaConversions`/`JavaConverters` imports. Why: wrappers, not copies; mutation shows through and
  an immutable Scala collection's Java view throws on write. [CollectionConverters overview]

### Tests

- **`assertEquals(obtained, expected)` in that order.** Signal: a literal as munit's first
  argument; `assertEquals[Any, Any]`. Why: the diff reads backwards and the cast defeats the
  `Compare` type class. [munit assertions]
- **`intercept` the most specific exception.** Signal: `intercept[Exception]`,
  `intercept[Throwable]`. Why: a setup bug passes; if the type cannot be named the code should throw
  a better one. [Databricks, munit assertions]
- **Could this test pass while the thing it checks is false?** Signal: a filter that matches zero
  tests (munit's `--` needs a leading wildcard), a smoke test accepting a 404, `assert(true)` after a
  side effect. Why: break the behaviour once and watch it go red. [general checklist, Tests]
- **`eventually` is for integration; retry on the value, assert the identity.** Signal:
  `eventually { assert(db.read().nonEmpty) }; assert(db.read().head == x)`; `eventually` on I/O with
  default patience; `eventually` in a unit test. Why: the second read is stale and 150 ms is tuned
  for memory; `IntegrationPatience`. [ScalaTest Eventually]
- **No `Thread.sleep` or wall clock in tests.** Signal: `Thread.sleep(500)` before an assertion; a
  timer actor tested in real time. Why: `ManualTime.timePasses` and `expectNoMessageFor` are
  deterministic and fast. [Pekko testing-async]
- **Fixtures in `beforeAll`/`FunFixture`; `super.beforeAll()` when overriding.** Signal: `val db =
  connect()` in the suite body; a testcontainers munit suite overriding `beforeAll` without `super`.
  Why: discovery instantiates the class and `afterAll` may never run; without `super` the containers
  never start. [munit fixtures, testcontainers-scala]
- **Container lifecycle matches cost; serialised suites stay serialised.** Signal:
  `TestContainerForEach` on Postgres or Kafka; a diff removing `Tags.limit(Tags.Test, 1)`. Why: one
  container per test, or contending containers, turn seconds into minutes. [testcontainers-scala]
- **No fixed ports in tests.** Signal: a hard-coded port in a suite or a fixture. Why: it cannot run
  beside a developer's local server or another suite; bind to port 0 and read the port back.
  [reviewer experience]
- **A `-D` switch is forwarded to the forked test JVM.** Signal: a new `sys.props` read with no
  matching `Test / javaOptions` entry. Why: with `Test / fork := true` the property lands in a JVM
  that runs no tests and the switch is a silent no-op. [sbt forking]

### Build and dependencies

- **Test and compile-time dependencies are scoped.** Signal: `munit`, `scalatest`, `testcontainers`,
  `pekko-actor-testkit-typed` without `% Test`; a compiler plugin without `% Provided`. Why: it
  ships into production classpaths. [sbt library dependencies]
- **`%%` for Scala libraries, `%` for Java; `for3Use2_13` only documented.** Signal: `"org.foo" %
  "lib"` on a Scala artifact; `cross CrossVersion.for3Use2_13` in a published library. Why: wrong
  binary suffix; users get `x_2.13` and `x_3` both on the classpath. [sbt, cross-build]
- **Versions pinned, never ranges.** Signal: `"2.9.+"`, `"[1.0,)"`, `latest.integration`; a
  `version :=` literal. Why: "the effective version keeps changing"; centralise versions in one
  object under `project/`, and derive the artifact version from git tags (sbt-dynver) rather than a
  literal where the project does. [sbt]
- **`scalacOptions` are not relaxed to make a PR compile.** Signal: a diff removing `-Werror`,
  `-Wunused`, `-Wvalue-discard`; a wholesale `-Wconf:...:s`; `Test / scalacOptions` dropping lints.
  Why: every filter needs a reason in the diff. [compiler-options]
- **MiMa guards every published module.** Signal: a published module without
  `mimaPreviousArtifacts`; a `ProblemFilters.exclude` with no justification; a removed public method,
  added parameter or new case class field in a minor release. Why: binary breaks are MAJOR;
  `mimaReportBinaryIssues` fails on an empty previous set so it cannot be skipped quietly. [MiMa]
- **Defaults, case class shape and synthesized names are binary API (Scala 3 for names).**
  Signal: a changed default value, a new case class field, an anonymous public `given`, a top-level
  `def` moved to another file (`Foo$package` changes). Why: each breaks binary compatibility with no
  visible source change. [binary-compatibility, givens, package-objects]
- **`.scalafmt.conf` churn and major bumps each get their own PR.** Signal: a `version` bump, a
  `runner.dialect` change or new `rewrite.rules` mixed with logic; a Steward PR mixing a major with
  a scalafmt bump. Why: the reformat hides the change; the dialect must match the compiler
  (`scala213` cannot parse `given`). [scalafmt configuration]
- **One actor-library line; no Akka beside Pekko.** Signal: `com.typesafe.akka` arriving
  transitively in a Pekko build; `pekko-http` at another version than `pekko-actor`. Why: Akka 2.7+
  is BSL-licensed, which is a licence decision and not a version bump, and mixed Akka/Pekko or mixed
  Pekko versions fail at runtime. [Pekko; reviewer experience]

### API design and encapsulation

- **Smallest visibility that works.** Signal: new public members on an internal class. Why:
  "widening later is easier than narrowing"; `private`, then `private[module]`. [Effective Scala]
- **Classes meant for extension are `open`, the rest `final` (Scala 3).** Signal: a bare `class Foo`
  extended from another file. Why: ad hoc extension warns from 3.4; `open` documents the contract,
  `-language:adhocExtensions` covers test mocks. [open-classes]
- **Invariants need a private constructor and a companion factory.** Signal: a `case class` with
  `require` that `copy` can violate; `def apply` on a class, not its companion. Why: Scala 3 hides
  `copy`/`apply` behind a private constructor (2.13 needs `-Xsource:3`); expose `withXxx` for binary
  stability. [Databricks, binary-compatibility]
- **No overloading with default arguments.** Signal: `def f(a: Int, b: Int = 0)` beside `def f(a:
  String)`. Why: resolution confuses readers and Java callers, and defaults are binary API; distinct
  names. [wartremover DefaultArguments, Databricks]
- **Type class instances and extension methods live in the companion (Scala 3 for extensions).**
  Signal: `given Ordering[Foo]` or `extension (x: Foo)` in a `Utils` object when `Foo` is yours.
  Why: companions are in implicit scope, so coherence is automatic and no call site imports; stray
  instances mean two orderings for one type. [derivation, givens, domain-modeling-fp]
- **`override` is always written.** Signal: `def run(): Unit = …` implementing a trait method
  without `override`. Why: a renamed parent becomes a compile error, not an orphan. [Databricks]
- **By-name parameters only for control-construct DSLs, last position.** Signal: `def retry(op: =>
  T, times: Int)`; a by-name evaluated several times with side effects. Why: re-evaluation is
  invisible at the call site; `() => T` when it is the point. [Effective Scala, Databricks]
- **Wire names stay separate from Scala names.** Signal: a macro or `getClass.getSimpleName`
  deriving a protocol string, journal manifest or discriminator from a Scala identifier. Why: a
  rename must not change the protocol, or in-flight requests and persisted references break during
  a rolling deploy. [reviewer experience; general checklist, API and compatibility]

### Idioms and Scala 3 syntax

- **No Scala 2 implicit machinery in Scala 3 code (Scala 3).** Signal: `implicit val`, `implicit
  def`, `implicit object`, `implicit class` in a Scala 3 build. Why: `given`, `using`, `extension` and
  `Conversion` say it once; two vocabularies double the reading cost. [relationship-implicits]
- **No spellings Scala 3.4 deprecates (Scala 3).** Signal: `List[_]`, `import a._`, `{b => c}`, `xs:
  _*`, `private[this]`, `var x = _`, `A with B` as a type, `def f() {`, `package object`. Why: `?`,
  `*`, `as`, `private`, `uninitialized`, `&`, `: Unit =` and top-level definitions replace them;
  errors under `-source future`. [wildcards, imports, vararg-splices, 3.4.0 blog]
- **No `Enumeration` in new code.** Signal: `extends Enumeration`, `Value`. Why: reflective, weak
  exhaustiveness, no parameters; Scala 3 `enum` or sealed case objects. [enums]
- **Givens: one canonical value per type, named in public APIs, no defaults (Scala 3).** Signal:
  anonymous `given Ord[Int] with` in a published library; a `using` parameter with a default. Why:
  the synthesized name is binary API, a given is for "a single canonical value", and a default
  shadows a given depending on the call shape. [givens, using-clauses]
- **Implicit conversions are a design smell.** Signal: `given Conversion[A, B]` or `implicit def
  a2b` without `import scala.language.implicitConversions`; a view bound `<%`. Why: the compiler
  warns on the definition, both guides say convert explicitly, views are gone in Scala 3.
  [implicit-conversions, Databricks]
- **Union types must be ascribed (Scala 3).** Signal: `val x = if c then a else b` where `A | B` is
  expected. Why: the compiler infers a common supertype, often `Matchable`, never a union; a sealed
  `enum` for a closed, named set. [types-union]
- **Refutable patterns in `val` and `for` need `case` or `@unchecked` (Scala 3).** Signal: `val
  Some(x) = opt`, `val h :: t = xs`, `for (a, b) <- pairs`. Why: warns since 3.2 and the generator
  no longer filters; `for case (a, b) <- pairs` or a `match`. [pattern-bindings]
- **No `return` inside a lambda or `for` body.** Signal: `return` in a `foreach`, `map` or `for`
  block. Why: a thrown `NonLocalReturnControl`, deprecated since 3.2, catchable by a careless `catch`,
  possibly on another thread; `boundary`/`break` or restructure. [nonlocal-returns]
- **Surface style only where the formatter does not own it.** Signal: braces and indentation mixed
  in one scope, `if (x) then y`, `xs map (_.f)`, `javaList add item`, `def size()` on a pure
  accessor, a new `def >>` without `@targetName`. Why: one style per file, infix for pure operators,
  parentheses mark side effects, a symbolic name needs a readable JVM name; skip it all when
  `.scalafmt.conf` sets `rewrite.scala3.*` or `AvoidInfix`. [indentation, style/method-invocation]

## Severity

**Blocking**
- Actor state is touched only from its own message handler
- No blocking on a shared dispatcher (except a documented virtual-thread runtime)
- Event handlers are pure; side effects in `thenRun`; all state in `State`
- Persisted and wire types are a versioning boundary
- Every ask has a timeout and the receiver always replies
- No partial accessor on a possibly-empty value; no `null` in Scala code; no `asInstanceOf`
- Never catch `Throwable`, `Exception` or `case _ =>` blindly
- Messages, events and state are immutable
- `==` on `Array` compares references; `==` between unrelated types when it decides behaviour
- An `Iterator` is consumed once
- Nothing reads a `val` before it is initialised
- Fixtures call `super.beforeAll()`; a test that cannot fail; no fixed ports; `-D` forwarded
- MiMa guards every published module; `scalacOptions` not relaxed; versions pinned

**Should fix**
- No Scala 2 implicit machinery; no spellings 3.4 deprecates; no `Enumeration`
- Sealed hierarchies, `final` leaves, no catch-all; `override` always written; `open` or `final`
- `Seq` defaults to `List`; no appending in a loop; mutable collections named at the use site
- Expected failures in the type; `recover` only what you mean; `Either` and `Try` keep their error
- One codec per type in the companion; instances in the companion; givens named; conversions
- No `return` in a lambda; by-name only for DSLs; no overloading with defaults; private constructor
  for invariants; refutable patterns with `case`
- `eventually` is for integration; no `Thread.sleep` in tests; `intercept` the most specific
- Test dependencies scoped; `for3Use2_13` only documented

**Nit**
- Surface style only where the formatter does not own it: infix, parentheses, `then`/`do`, end
  markers, fewer braces on one-liners, symbolic names without `@targetName`
- Interpolation over `+`, naming, parameter lists without reason, structural types (reference)

## Where the sources disagree

- `Try` or `Either` in APIs: follow the repository's convention; if none, prefer
  `Either[SealedError, A]` because it names expected failures and keeps `Try` for code that throws.
- `return` as a top-level guard or never: follow the repository's convention; if none, prefer none
  in code written in a functional style. Both sides agree it is wrong in a closure.
- By-name parameters avoided or allowed for DSLs: follow the repository's convention; if none,
  review evaluation count and clarity rather than presence, because the Scala 3 reference uses them.
- Braces always or omitted on one-liners: the formatter decides, never the reviewer.
- `enum` or sealed trait (Scala 3): follow the repository's convention; if none, prefer `enum` for
  plain ADTs and a sealed trait where cases need companions, per-case methods or variance.
- Annotation casing: follow the library's own spelling (`@tailrec`, `@nowarn`, `@targetName`).
- `private[this]`: in Scala 3 it reduces to "do not touch another instance's private field"; in
  2.13 the modifier is still meaningful, so keep it there.
- `null` in hot paths or never: follow the repository's convention; if none, prefer `Option` or
  `T | Null` under `-Yexplicit-nulls`, confining `null` to a measured hot path behind a private API.
- Blocking in a `Future` or handler: forbidden on a Pekko default dispatcher; allowed on a
  virtual-thread executor or a dedicated blocking dispatcher where the repository documents it.
- `eventually` defaults: require explicit patience in any `eventually` that touches I/O, because the
  150 ms default is tuned for in-memory checks.
- `-Wnonunit-statement` or `-Wvalue-discard`: neither subsumes the other; prefer both.
- `implicit` deprecation: no date is set and 3.7/3.8 compile it silently, so preferring
  `given`/`using` is a consistency rule, not a compiler-driven one.
- Unverified in a primary source: scalafmt's rewrite-rule page, `Future.sequence` fail-fast
  semantics, the classic `sender()`-in-callback warning, NaN equality. Phrase findings resting on
  these as questions when the context is unclear.
