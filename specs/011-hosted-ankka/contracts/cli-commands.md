# Contract: CLI changes

One command gains three options. Nothing else changes.

## `ankka organizations create <id> --name <string> [--owner <subject> [--owner-email <email>] [--owner-name <string>]]`

- `--owner` names the first owner's subject. Only a platform administrator's login may use it;
  the control plane answers `403` otherwise and the CLI prints `not permitted: platform
  administrator role required to name an owner`.
- `--owner-email` and `--owner-name` are display details for that owner and are refused by the
  CLI's own parser when given without `--owner`.
- Without `--owner`, the body is `{"name": …}` as today.
- Output on success: `organization '<id>' created` (unchanged), or `organization '<id>' created
  for <subject>` when an owner was named.

## Refusals printed verbatim

The CLI already prints a `403`'s message after `not permitted:`; in an installation whose
creation policy is `platform-admin`, `ankka organizations create` from a non-administrator prints

```text
not permitted: organizations in this installation are created by the platform administrator; sign up at https://…
```

and exits non-zero. No new CLI code is needed for that.
