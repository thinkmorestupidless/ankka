# Implementation Plan: A Platform a Hosted Product Can Provision

**Branch**: `011-hosted-ankka` | **Date**: 2026-09-24 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/011-hosted-ankka/spec.md`, and the design treatment
it was written from, `docs/design/hosted-ankka.md`.

## Summary

Four small, independent changes to the platform so that a product outside this repository can
sign customers up and provision them on an installation, without the platform learning anything
about money:

1. **A creation policy.** `ANKKA_ORGANIZATION_CREATION` (`open`, the default, or `platform-admin`)
   and an optional `ANKKA_SIGNUP_URL`, read once at startup into an `OrganizationPolicy` the way
   `AuthConfig` and `DeployConfig` are, and enforced in `OrganizationEndpoint` — the endpoint, not
   the entity, because who may issue a command is the endpoint's question in this codebase.
2. **Create for an owner.** `CreateOrganization` gains an optional `owner`; a platform administrator
   naming one reaches a *new* entity command, `create-for-owner`, whose event
   `OrganizationCreated` carries the owner in a new optional field. The old command keeps its
   payload so an in-flight create during a rolling update still decodes. Both the entity's fold and
   the listing view's fold seat the named owner.
3. **Publish `ankka-controlplane-api`.** Remove `publish / skip`; it already depends on `core`
   alone. The Scala SDK stays "six libraries a service depends on"; the seventh is documented as
   what a *client of the control plane* depends on.
4. **Prove the spoke.** `EndToEndClusterSuite` starts a second in-process control plane whose
   `AuthConfig` names the hub's issuer explicitly while its own base domain differs, and shows the
   hub's token accepted, the hub's issuer advertised, and a token from another issuer refused.

## Technical Context

**Language/Version**: Scala 3.9.0, JDK 21, sbt 1.12.15 (unchanged).

**Primary Dependencies**: none new. `controlplane-api` gains no dependency (FR-014); the CLI and
the control plane change only their own code.

**Storage**: the control plane's existing journal. One event gains an optional field with a `None`
default; no DDL change; pre-feature journals replay (`EventCompatibilitySuite`).

**Testing**: munit. A unit suite for `OrganizationPolicy.from` (both values, the refusal);
`TenancyEntitySuite` for the new command and fold; `AuthorizationMatrixSuite` for the owner option
under the default policy; a new `OrganizationCreationPolicySuite` (one `AnkkaTestKit`, restricted
policy) for the refusal, the administrator's success and "every other route unchanged";
`EventCompatibilitySuite` for the old JSON; `EndToEndClusterSuite` for the spoke; the two reference
suites regenerated; `TemplateSuite` unchanged (the template does not need the seventh artifact).

**Target Platform**: unchanged.

**Project Type**: additive changes to one application (`controlplane`), one wire library
(`controlplane-api`, now published), the CLI, the build, and documentation.

**Performance Goals**: none new. The policy check is one boolean and one set lookup on a principal
already in hand; the owner path is one entity command, same as today's create.

**Constraints**: default behaviour byte-for-byte as before (SC-001 — no existing test changes);
`controlplane-api` depends on `core` only; the control plane learns no product concept; wire names
are a versioning boundary, so a changed payload is a new command, not an edited one.

**Scale/Scope**: ~20 files touched. The largest piece is the spoke case in the k3s suite; the
riskiest is the build change, because it is the release path.

## Constitution Check

`.specify/memory/constitution.md` is the unfilled template; `CLAUDE.md` governs.

| Principle | How this plan keeps it |
|---|---|
| Effects are inert data | the new command persists one event; the policy and the owner check produce no effect at all — they refuse before the entity is called |
| Cross-entity checks live in the endpoint | the policy is not even cross-entity; it is installation-level, and lives in the endpoint beside `Authorization` |
| The wire name is a versioning boundary | `create` keeps its `String` payload; `create-for-owner` is a new name with a new payload |
| Module dependency direction | `controlplane-api` still depends on `core` only; publishing changes coordinates, not edges |
| Events replay | `OrganizationCreated.owner` defaults to `None`; the fold falls back to today's derivation from the actor |
| Only a tag publishes | removing `publish / skip` adds an artifact to the same `sonaRelease`; nothing else in the release path moves |
| A page stands alone; reference facts are generated | the route and CLI pages are regenerated by their suites; the policy is documented in prose on the identity page, where the control plane's other settings already are |

No violations; the Complexity Tracking table is empty.
