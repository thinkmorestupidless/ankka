## Implementation strategy

**MVP is Phase 1 + Phase 2 + US1** (T001–T024): a typed task runs to completion through the
built-in tools, is readable and awaitable, in Scala and Python, with the sample answering a
question. That is a demonstrable autonomous agent, though not yet a durable one. **US2 and US3**
make it safe to run unattended (it comes back, and it stops), and together with US1 they are the
P1 set the spec names — ship nothing before those three. US4–US7 each add one property a reader
of the spec would expect and each is one checkpoint; US8 is what makes any of it true for the
reader who arrives with one page.

Ship in one pull request as one release: the protocol minor, the new `ComponentKind` and the
`AgentRuntime.descriptors` change move together, and a sidecar that speaks 1.2 to an SDK that
does not know the kind is harmless (a minor is additive), so there is no intermediate state worth
a release of its own. Land the phases as commits in this order so the branch is demonstrable at
each checkpoint.

## Format validation

foundational and polish tasks carry no story label; story tasks carry exactly one.
