# Tasks: Service Topology — What a Service Runs and How It Connects

**Input**: Design documents from `/specs/019-service-topology/`

**Prerequisites**: [plan.md](./plan.md), [spec.md](./spec.md), [research.md](./research.md),
[data-model.md](./data-model.md), [contracts/](./contracts/), [quickstart.md](./quickstart.md)

**Scenarios**: the acceptance scenarios live in `features/` (the spec names them under each user
story), in the words of the root `GLOSSARY.md`. A task that tests a story's behaviour covers that
story's scenarios, by name.

**Tests**: included. SC-008 requires every scenario the spec names to be run, and to fail when the
behaviour is removed, so each test task ends by breaking the behaviour once and watching it go red.
A feature file one suite can run whole is run by `GherkinSuite`, each scenario as written; a
scenario with no step definition fails. The scenarios no suite can reach are tests named after
them (research R13 says which file is run by what). Where a task says "case", it means a
`test(...)` in the named suite, for something no scenario states.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: can run in parallel — different files, no dependency on an incomplete task
- **[Story]**: US1 (declared topology, local), US2 (observed calls, local), US3 (calls to other
  services), US4 (deployed topology in the installation's console), US5 (documentation)

## Implementation Strategy

### MVP

Phases 1-3 (T001-T015): the declared topology of any local service in any language. It is exact,
needs no traffic and touches no host.

### Increments

1. **US1** — declared topology, local. Ship.
2. **US2** — the caller, counting, call edges. The riskiest increment: it adds spans to four kinds
   of host and a write on every call. T031's gate decides whether it ships as designed.
3. **US3** — external services.
4. **US4** — the deployed view. A release boundary: a workload needs a runtime with the `observe`
   listener, so the release that carries it also carries the operator change, and an older workload
   reports `unsupported` until it is redeployed.
5. **US5** — docs, written with each increment and finished here.

### Notes

- Commit per task or per small group, staging paths by name.
- Each test task ends by breaking the behaviour once (SC-008). A case that stays green when its
  behaviour is removed is not finished.
- Retry on the value that changes (a count), assert the identity that does not (the pair's names).
- No suite binds a fixed port: `HttpServer.at("127.0.0.1", 0)` locally; 7628 only inside pods.
