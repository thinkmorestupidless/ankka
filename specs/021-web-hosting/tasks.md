# Tasks: Web Hosting — A User Interface Deployed Beside Its Services

**Input**: Design documents from `/specs/021-web-hosting/`

**Prerequisites**: [plan.md](./plan.md), [spec.md](./spec.md), [research.md](./research.md),
[data-model.md](./data-model.md), [contracts/](./contracts/), [quickstart.md](./quickstart.md)

**Tests**: included. Every acceptance scenario is a scenario in a living feature, and this
repository's rule is that each ends up as a test that fails without the feature. Six feature files
are run whole by `GherkinSuite`; the other four are tests named after their scenarios (R16). Where
a task says "case", it means a `test(...)` in the named suite. Before relying on any check, ask
whether it could pass while the thing it checks is false, and break the behaviour once to see it
go red.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: can run in parallel — different files, no dependency on an incomplete task
- **[Story]**: US1 (an interface deployed with the CLI), US2 (the process calls services as
  itself), US3 (mounts), US4 (the same interface on a developer's machine), US5 (template, sample,
  documentation)

Paths are repository-relative. Abbreviations, each followed by
`/scala/com/thinkmorestupidless/ankka/<package>`: `API` = `controlplane-api/src/main` … `controlplane/api`,
`APIT` its `src/test`; `CRD` = `crd/src/main` … `crd`; `OP` = `operator/src/main` … `operator`,
`OPT` its `src/test`; `CP` = `controlplane/src/main` … `controlplane`, `CPT` its `src/test`;
`CLI` = `cli/src/main` … `cli`, `CLIT` its `src/test`; `RT` = `modules/runtime/src/main` … `runtime`;
`H` = `modules/http/src/main` … `http`, `HT` its `src/test`; `PC` = `proxy-core/src/main` … `proxy/core`,
`PCT` its `src/test`; `PX` = `proxy/src/main` … `proxy`, `PXT` its `src/test`. `K` =
`kustomization`; `F` = `features/web-hosting`. "R*n*" is a section of `research.md`;
"contract *name*" a file in `contracts/`.

Three rules for every task:

- stage this feature's paths by name on every commit; never `git add -A`;
- every listener a test starts binds port 0 on loopback, and every port a test tells a program is
  one it found free;
- a suite names an image by `BuildInfo.imageTag`, never by `:latest` or a literal tag.

## Implementation Strategy

**MVP is US1**: an interface that calls nothing, or whose backends are exposed, is fully deployed
by it. Stop there and check the story's independent test before going on.

Then one story at a time, each ending at its checkpoint: US2 makes backends private, US3 makes a
single-page app need no proxy of its own, US4 makes it the same on a laptop, US5 makes it
something a newcomer can start from.

Three rules for the whole feature, from the plan and the analysis: the unchanged-rendering
fixtures are never regenerated after T002; no task builds on the JDK's HTTPS server until T005
has passed; and no descriptor, test or sample reads a Secret the platform issues.
